## 只增不改（Additive Only）

| 变更 | 允许 | 操作 |
|------|------|------|
| 新增事件 `type` | ✅ | 加进 schema enum + `events.py` |
| 新增 artifact `kind` | ✅ | 同上；前端未注册的 kind 会显示提示而不是崩溃 |
| 给事件加**可选**字段 | ✅ | 加进 schema |
| 给事件加**必填**字段 | ⚠️ | 先加可选、双写，稳定后再收紧 |
| 改字段名/语义、删事件 | ❌ | 走 ADR（`docs/adr/`），同步改 schema + `events.py` + 前端消费方 |

---

## 谁维护

**R1（架构/集成）是唯一审批人。** 其他人可以提 PR 新增枚举值，
但涉及语义变更必须经 R1 确认并留下 ADR。

理由：契约是所有并行开发的地基，没有单一负责人就会慢慢腐化，
最终表现为"前端说后端发的字段不对，后端说前端没按契约解析"。

## 自动化守卫

`scripts/smoke_test.py` 第 4 节会：

1. 读取 `events.schema.json` 的 `type` 白名单；
2. 真实跑一遍知识问答与解题流程；
3. 比对实际发出的所有事件类型是否都在白名单内。

任何越界事件都会让自检失败 —— 这就是契约不会被悄悄破坏的原因。

```bash
python scripts/smoke_test.py     # 第 4 节：契约合规
```
