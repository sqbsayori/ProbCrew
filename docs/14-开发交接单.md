## 一、产品是什么（一句话）

**一个能读懂学生正在看的那个网页、并且答案可被验证的辅助学习工具。**

两种交付形态，共用同一套内核：

- **形态 A 页面内助手**：一行 `<script>` / 油猴脚本 / 浏览器扩展，直接读 DOM
- **形态 B 独立外部助手**：扩展侧边栏等独立入口，经**一次性授权**后读取页面

> ⚠️ 别承诺"隔空抓取"：浏览器同源策略决定，从外部读页面**必须先获得该页面执行权限**。

## 三、怎么加东西（四条，都不用改公共文件）

这一节是**并行开发不打架的关键**，务必按它做。

| 想加什么 | 放哪 | 要求 |
|---|---|---|
| **Agent** | `backend/app/agents/<名字>.py` | 定义 `SPEC = AgentSpec(...)` + `async def run(state, ctx)`；`_router.py` 里加意图关键词（如需路由） |
| **工具** | `backend/app/tools/<名字>.py` | 用 `@tool("name", "中文名", "说明", owner="R?")` 装饰 async 函数；**返回结构用三态** `ok` / `empty` / `available` |
| **接口** | `backend/app/api/<名字>.py` | 导出 `router = APIRouter(...)`；改完跑 `python scripts/gen_api_contract.py` |
| **页面** | `frontend/app/features/<名字>/` | `feature.json` + `index.js`（导出 `mount`/`unmount`）；跑 `python scripts/gen_registry.py` |
| **投递方式** | 只写交付层 | **不得修改 `extractor.js` 与后端**（这是架构红线） |

## 四、必须遵守的约定（踩过坑的）

1. **前端不硬编码后端地址**：一律 `data-api` → `location.origin` → 配置块兜底（详见 `docs/13`）
2. **契约只增不改**：改字段走 ADR；`contracts/api.md` 由脚本生成，禁手工编辑
3. **事件协议是唯一约定**：14 种类型，加类型要同时改 `events.py` + `events.schema.json`（契约校验会拦）
4. **失败必须显式**：读不到内容 / 检索为空 / 校验不过 —— 都要**说出来**，不允许沉默降级
5. **绝不修改那 8 个原始动画文件**：需要注入时由后端在响应时插（`api/raw_live.py`）
6. **测试是门槛**：新增能力必须带一个能拦住回归的测试；本地全绿才算完成
7. **分支**：`feature/xxx` →（squash）`dev` →（merge）`main`。**绝不 squash `dev`**
8. **不提交**：`backend/data/`、`.env`、任何 `*.sqlite`、任何学生数据

## 六、第一批任务（按优先级，各自独立可并行）

### 任务 1 · 检索升级（最高杠杆）⭐ ✅ 已完成（真实权重已跑通）

**为什么**：`kb_search` 现在是关键词匹配；**每个 Agent 都要调检索**，这是整条链的地基。

**做什么**：
1. 接入中文嵌入模型 **BGE-M3**（或 `bge-large-zh-v1.5`），本地跑，数据不出校
2. 接入重排 **bge-reranker-v2-m3**
3. **混合检索**：BM25 + 向量融合（**必须保留 BM25** —— BGE-M3 对 LaTeX 很弱，而我们语料全是公式）
4. 检索结果带出处（章节/小节），前端可点开

**验收**：同一批 **≥30 个问题**，产出「升级前 vs 升级后 top-3 命中率」对比数据，写进文档。
**达成情况**：40 题标尺，四种配置对比，数据见 **`docs/16-检索升级对比.md`**（本轮**真实权重**已跑通）。

**改动位置**：新增 `backend/app/tools/embedding.py`、`reranker.py`；改造 `kb_search.py`（**保持返回结构兼容**，三态不变）。

**落地记录**：

| 做了什么 | 文件 |
|---|---|
| 嵌入层（BGE-M3 / 本地权重；缺权重时降级并**显式标注**） | `backend/app/tools/embedding.py` |
| 重排层（bge-reranker-v2-m3 交叉编码；不可用返回原因） | `backend/app/tools/reranker.py` |
| 混合检索：BM25 + 向量（加权 RRF）+ 重排，**字段只增不改**、出处到行号 | `backend/app/tools/kb_search.py` |
| 检索配置（模型名 / 权重目录 / 候选数 / 阈值 / 开关） | `backend/app/config.py`、`.env.example` |
| 权重一次装好（含镜像/代理回退、缺文件补齐） | `scripts/setup_models.py`、`scripts/repair_model_cache.py` |
| 40 题标尺 + 对比脚本 | `scripts/retrieval_questions.tsv`、`scripts/eval_retrieval.py` |
| 对比数据（真实 BGE-M3 + reranker） | **`docs/16-检索升级对比.md`** |
| 回归测试 19 项（接口兼容 / 三态 / 出处 / 融合性质 / 命中率闸门） | `backend/tests/test_retrieval.py` |
| 健康检查暴露检索层状态（权重装没装一眼可见） | `backend/app/api/system.py` |

**实测结论（40 题，详见 docs/16）**：

| 配置 | top-1 按章 | top-3 按章 | top-1 按小节 | top-3 按小节 | 单次耗时 |
|---|---|---|---|---|---|
| ① 仅 BM25（升级前基线） | 85.0% | 97.5% | 76.5% | 91.2% | 0.9 ms |
| ② 仅向量（BGE-M3） | 90.0% | 97.5% | 85.3% | 94.1% | 70 ms |
| ③ 混合（融合，不重排） | **92.5%** | 97.5% | 82.4% | 91.2% | 75 ms |
| ④ 混合 + 重排 | 90.0% | 97.5% | **85.3%** | 94.1% | 2243 ms |

* **升级点在于"排得准"**：top-3 四种配置都是 97.5%（小语料上 BM25 已经很强），
  但 top-1 按小节 76.5% → 85.3%；
* **重排在 CPU 上很贵**：+2.2s 换来的收益有限 → 交互式问答建议走 ③（融合不重排），
  重排用于离线评估/批量整理，可用 `RERANK_CANDIDATES` 压成本；
* **BM25 必须留**：与 docs/12 的判断一致，现已被数据证实。

**权重装在哪**：`backend/data/models/`（约 4.3 GB，**已 gitignore，绝不进仓库**），
由 `scripts/setup_models.py` 下载、`.env` 里的 `MODELS_DIR` 指向它。
换机器只需重跑一次（脚本会自己试镜像/代理，失败可换 `--target`）。

```powershell
python scripts/setup_models.py          # 会自动把 MODELS_DIR 写进 .env
python scripts/eval_retrieval.py --out docs/16-检索升级对比.md
```

**两个不报错的坑（已写进代码注释）**：`tokenizer.json` 缺失会让 `AutoTokenizer` 静默回退到
慢速实现、把中文全编码成 `<unk>`（向量恒等）；BGE-M3 官方池化是 **CLS**，用 mean pooling 会掉区分度。
