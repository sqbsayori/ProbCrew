# 02 · 事件契约

> **这是本项目唯一的跨端约定。** 谁都不能私自改已有字段。
> 权威定义：`contracts/events.schema.json`（机器可读）+ `backend/app/kernel/events.py`（实现）。

---

## 1. 为什么是"事件"而不是"接口返回 JSON"

一问一答式 API 的问题是：**多 Agent 协作的过程被藏起来了**。
用户只看到一个最终字符串，无法知道是谁回答的、调了什么工具、有没有被校验过。

用事件流之后：

- 前端的「协作轨迹」面板可以**实时**画出 Orchestrator 路由、Agent 并行、工具调用、校验、HITL；
- 一次 run 的全部事件按序落盘就是一条**完整轨迹**，可直接做演示复盘与后续评估数据集；
- 新增事件类型是**向后兼容**的（老前端忽略未知类型即可）。

---

## 2. 传输格式

`POST /api/chat/stream` 与 `POST /api/hitl/{run_id}/resolve` 都返回 `text/event-stream`：

```
data: {"type":"run.start","ts":1730000000.1,"run_id":"run_ab12","session_id":"s_x","query":"什么是贝叶斯公式？"}

data: {"type":"plan","ts":1730000000.4,"run_id":"run_ab12","intent":"knowledge","steps":[{"agent":"knowledge","label":"Knowledge Agent 知识讲解"}],"reason":"命中「知识点讲解」特征词"}

data: {"type":"agent.start","ts":1730000000.4,"run_id":"run_ab12","agent":"knowledge","label":"Knowledge Agent 知识讲解"}

...（大量 agent.delta / tool.call / tool.result / artifact）...

data: {"type":"run.end","ts":1730000002.9,"run_id":"run_ab12","status":"ok","final_answer":"## 结论先说\n..."}

event: end
data: {}
```

**约定**：
- 一条事件 = 一行 `data: ` + 一个 JSON 对象；`\n\n` 结尾。
- 报文里**不会出现 `null` 字段**（后端 `exclude_none=True`），减小体积。
- 流末尾固定发一帧 `event: end`，前端据此确认流已正常关闭。
- 中文不转义（`ensure_ascii=False`），后端已统一 UTF-8。

## 3. 事件清单

| 事件 | 何时发 | 关键字段 | 前端典型反应 |
|------|--------|---------|-------------|
| `run.start` | 运行开始 | `run_id`, `session_id`, `query` | 清空轨迹，记录 runId |
| `context.received` | 助手已读取页面上下文 | `summary`, `data{title,chars,formula_count,frame_count,outline,…}` | 面板顶部显示"读到了什么"；读不到时黄色警告 |
| `plan` | Orchestrator 决策完成 | `intent`, `steps[{agent,label}]`, `reason` | 渲染调度计划胶囊 + 路由理由 |
| `agent.start` | 某 Agent 开始 | `agent`, `label`, `step` | 该 Agent 行进入"运行中" |
| `agent.delta` | LLM 吐出一段增量 | `agent`, `text` | 追加到该 Agent 的流式块（rAF 节流重渲染） |
| `agent.end` | 某 Agent 结束 | `agent`, `ok`, `duration_ms`, `summary` | 标记完成/失败，显示耗时 |
| `tool.call` | 工具调用开始 | `agent`, `tool`, `args` | 在 Agent 行下加工具胶囊，圆点闪烁 |
| `tool.result` | 工具调用结束 | `tool`, `ok`, `data`, `duration_ms` | 圆点变绿/变红，`title` 显示耗时 |
| `artifact` | 产出结构化内容 | `kind`, `payload` | 按 kind 渲染（见 §4） |
| `verification.report` | 所有 Agent 跑完、聚合之前 | `data`（验证报告全量）, `summary`, `ok` | **显著展示验证级别 A/B/C/D**，让用户知道这个答案被验证到什么程度 |
| `hitl.request` | 图在 `interrupt()` 挂起 | `hitl_id`, `agent`, `draft`, `options[]` | 弹出黄色 HITL 卡片，暂停态 |
| `hitl.resolved` | 用户已处理 | `action`, `final` | 收起卡片，继续生成 |
| `run.end` | 运行结束 | `status`, `final_answer` | 用聚合答案替换逐 Agent 块 |
| `error` | 出错 | `message`, `agent?` | 红色提示，结束运行 |

**心跳/未知类型**：前端 `trace.js` / `run-panel.js` 的 `switch` 都有 `default: break`，
遇到不认识的事件**必须忽略**，绝不能抛错。这是契约的兼容性保证。

### 关于 `verification.report`（M1 新增）

这条事件是主线「正确性保障链」的对外体现，结构定义在
**`contracts/verification.schema.json`**。要理解的只有一件事：

> **绝不允许在没有验证报告的情况下输出解答。**

前端必须**显著**展示验证级别，不能藏在折叠面板里 —— 因为
「A 级：已通过数值重算」与「D 级：未做自动验证」对用户的意义完全不同。
笼统显示"已校验"是**不允许**的，那是在误导用户。

## 4. Artifact 的 payload 结构

`artifact` 是"结构化产出"的载体。新增 `kind` 属于兼容扩展；**修改已有 kind 的字段属破坏性变更**（需走 ADR）。

### 4.1 `animation` —— 交互动画

```json
{
  "kind": "animation",
  "payload": {
    "id": "bayes",
    "title": "贝叶斯公式",
    "url": "/animations/_raw/贝叶斯公式(g).html",
    "category": "概率基础",
    "description": "通过先验、似然和后验的动态变化，理解贝叶斯更新思想。",
    "reason": "与「什么是贝叶斯公式？」知识点相关（匹配度 5.21）",
    "controls": { "play": "#playBtn", "pause": "#pauseBtn", "reset": "#resetBtn", "step": "#stepBtn" }
  }
}
```

### 4.2 `formula` —— 公式卡

```json
{ "kind": "formula",
  "payload": { "title": "关键公式",
    "items": ["P(A)=\\sum_{i=1}^{n}P(B_i)P(A\\mid B_i)", "..."] } }
```
`items` 是 **LaTeX 源串**，前端用 KaTeX 渲染。

### 4.3 `steps` —— 解题步骤

```json
{ "kind": "steps",
  "payload": { "title": "解题步骤", "count": 4,
    "steps": [ { "index": 1, "title": "设事件", "body": "Markdown + LaTeX" } ] } }
```
Verifier 会读 `payload.count` 判断步骤是否完整（`>= 3`）。

### 4.4 `chart` —— 分布图（数据，不是图片）

```json
{ "kind": "chart",
  "payload": {
    "title": "正态分布 N(0, 1) 的 PDF / CDF", "dist": "normal",
    "name": "正态分布 N(μ, σ²)", "kind": "continuous",
    "params": { "mu": 0, "sigma": 1 },
    "mean": 0, "var": 1, "std": 1,
    "pdf": { "x": [-4, -3.9, ...], "y": [0.0001, ...] },
    "cdf": { "x": [ ... ], "y": [ ... ] }
  } }
```
**刻意不发 PNG**：发数据让前端用 Canvas 画，可交互、可换主题、体积小、无需 matplotlib。

### 4.5 `table` / `text`

```json
{ "kind": "table", "payload": { "title": "教材检索来源",
  "columns": ["章节","小节","相关度"], "rows": [["ch01 随机事件与概率","全概率公式与贝叶斯公式",0.3278]] } }

{ "kind": "text", "payload": { "content": "Markdown 文本" } }
```

## 5. 后端怎么发事件

Agent 里通过 `ctx` 发，**不要直接拼 JSON**：

```python
async def run(state, ctx):
    # 1) 流式 LLM —— 自动 emit agent.delta
    text = await ctx.stream_llm(SYSTEM_PROMPT, f"【用户问题】{state['query']}")

    # 2) 调工具 —— 自动 emit tool.call / tool.result（含耗时与入参）
    kb = await ctx.use("kb_search", query=state["query"], top_k=4)

    # 3) 结构化产物 —— 自动 emit artifact
    ctx.emit_artifact("formula", {"title": "关键公式", "items": [...]})

    # 4) 需要自定义事件时（谨慎，通常不需要）
    from ..kernel import events as E
    ctx.emit(E.ev("agent.delta", run_id=ctx.run_id, agent=ctx.agent, text="自定义"))
```

`agent.start` / `agent.end` 由 `kernel/graph.py` 的节点包装器统一发，
所以你**不需要**在 Agent 里手写它们 —— 这也是为什么所有 Agent 的耗时统计口径一致。

## 6. 前端怎么消费事件

```js
import * as api from '../core/api.js';
import { createTrace } from '../components/trace.js';

const trace = createTrace(host, { catalog: store.get('agents') });

await api.streamChat({ query, sessionId }, (e) => {
  trace.handle(e);                 // 轨迹面板
  if (e.type === 'artifact') {/* 渲染产物 */}
  if (e.type === 'run.end')  {/* 用 e.final_answer 替换流式块 */}
});
```

推荐直接用现成的 `createRunPanel()`，它已经把这些都接好了。

## 7. 变更纪律

| 变更类型 | 允许吗 | 需要做什么 |
|---------|--------|-----------|
| 新增一种 `type` | ✅ 兼容 | 加进 `events.schema.json` 的 enum；前端 `default` 分支会自动忽略 |
| 新增一种 artifact `kind` | ✅ 兼容 | 加进 enum；`artifacts.js` 加一个 renderer（未注册的 kind 会显示"未知产物类型"而不是崩溃） |
| 给已有事件**新增可选字段** | ✅ 兼容 | 加进 schema；老前端忽略 |
| 给已有事件**新增必填字段** | ⚠️ 需评估 | 先加可选、双写一段时间，再收紧 |
| 改已有字段名 / 语义 | ❌ 破坏性 | 必须走 `docs/adr/` 记录，并同步改 `events.py`、schema、前端消费方 |
| 删事件类型 | ❌ 破坏性 | 同上 |

**执行方式**：`scripts/smoke_test.py` 的第 4 节会拿真实跑出来的事件与 schema 白名单做比对，
任何越界事件都会让自检失败。这就是契约的自动化守卫。
