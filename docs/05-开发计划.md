## P1 · 契约联调 + 真实 LLM 全链路 + **真实平台验证**（2 周）

**目标**：把 mock 骨架变成"真模型跑得通、五个人各自开工"的状态，
并且**在真实课程平台上把助手跑通** —— 这是本阶段最高优先级的任务。

> ⚠️ **本阶段的第一优先级不是调 Prompt，而是"真机上能不能注入、能不能读到正文"。**
> 演示页 `/course/` 是我们自己造的，结构友好；真实超星/智慧树的 DOM 结构、
> CSP 策略、iframe 嵌套深度都可能让助手退化成一个普通聊天框。
> 这件事**必须在第 1 周就有结论**，否则后面所有工作都建立在假设上。

### 交付物
- 全组 API Key 统一配置，`/api/health` 显示 `deepseek`
- **真实平台验证报告**：`docs/notes/平台兼容性实测.md`（至少 1 个真实平台）
- 每个 Agent 用自己的真实 Prompt 跑通一轮，输出质量经过组内评审
- 契约评审完成，`contracts/events.schema.json` 冻结 v1
- CI（GitHub Actions）跑 `smoke_test.py` + 两个单测文件 + `gen_registry.py --check`

### 按角色的任务

| 角色 | 任务 | 具体文件 | 验收 |
|------|------|---------|------|
| **R1（主）** | **真实平台验证**：装油猴脚本，在超星/智慧树上实测注入、抽取、跨 frame 汇总；记录失败模式（CSP/iframe/懒加载） | `widget/probstat-assistant.user.js`、`docs/notes/平台兼容性实测.md` | 至少 1 个平台能读到课件正文；每个失败模式都有结论与对策 |
| R1 | 契约评审与冻结；Knowledge / Page Tutor 的 Prompt 调优 | `contracts/`、`agents/knowledge.py`、`agents/page_tutor.py` | 5 个问题回答无幻觉、公式全部渲染成功 |
| **R4（主）** | 助手组件打磨：形象动画、窄屏适配、平台样式冲突排查、拖动与位置记忆 | `widget/pet.js`、`widget/widget.css`、`widget/assistant.js` | 在真实平台上视觉正常、不遮挡平台关键按钮 |
| R2 | Orchestrator 路由准确率评测（含页面意图）；Verifier 规则补强 | `agents/_router.py`、`agents/verifier.py` | 20 条测试问句（含 8 条页面类）路由正确率 ≥ 90% |

| R5 | GitHub Actions：lint + 三个测试 + registry check；`docker-compose.dev.yml` | `.github/workflows/ci.yml` | PR 自动跑，红灯阻止合并 |

### 真实平台验证要回答的问题（按顺序）

1. **能不能注入？** 油猴 `@require` 方式是否被站点 CSP 拦掉？若被拦，`@match` 收窄后呢？
2. **能注入到几个 frame？** 打开 DevTools 数一下页面里有多少 iframe，
   我们的脚本进了几个？课件正文在哪个 frame 里？
3. **抽取质量如何？** 在真实页面上执行 `__PSA_ASSISTANT__.debugContext()`，
   看 `text` 是不是课件正文，而不是导航/侧栏/推荐位。
4. **划词能不能用？** 在课件正文里划一句话，悬浮球旁是否出现"解释这段"。
5. **视频进度读不读得到？** 播放器是原生 `<video>` 还是自定义实现？
6. **会不会打扰用户？** 悬浮球是否遮挡平台的关键按钮（下一页/提交作业等）。

### 验收标准
- `dev.ps1` 默认走真模型，一次知识问答端到端 < 10s（P95）
- **至少 1 个真实课程平台上，助手能读到课件正文并正确回答"这一页讲了什么"**
- 5 人各自跑通一次完整问答并截图
- CI 在 PR 上自动运行并通过

### 风险
| 风险 | 应对 |
|------|------|
| **真实平台 CSP 拦截注入** | 这是本阶段最大的未知。对策：优先用 `@require`；若仍被拦，退路是**浏览器扩展**（Manifest V3，content script 不受页面 CSP 限制）——架构上两者共用同一套 `widget/` 模块，只换投递层 |
| **课件在第三方域 iframe 里** | 收窄 `@match` 覆盖那个域；若平台把课件放在完全不可注入的沙箱里，则该平台只能读顶层内容（降级但可用） |
| 真模型输出格式不稳定，`steps` 解析失败 | Prompt 里把格式要求写死；解析失败时 Verifier 标记"步骤不完整"并触发 HITL，而不是静默降级 |
| Token 成本失控 | 见 §四 成本控制；页面上下文已做 12000 字硬截断 + 页内检索，不会把整页塞进 prompt |
| 路由规则覆盖不足 | `_router.py` 的关键词表按每周收集的真实提问持续追加（成本极低） |

## P2 · 真数据：内容入库 + Qdrant 混合检索（3 周）

**目标**：把 `kb_search` 从"本地 Markdown + bigram"换成真正的混合检索。
**这是本项目技术含量最高、也最容易翻车的一段，建议给足时间。**

### 前置：教室/教材素材
- 教材 PDF / Markdown（**由团队从课程教师处获取或自行整理，注意合规**）
- 教学大纲（章节划分与重点标注）
- 配套习题集（**优先要有解答的**）

### 交付物
- `knowledge-base/ingest.py`：PDF/MD → 统一 Markdown+LaTeX → 章节切分 → 512 token 切块（128 overlap）→ 嵌入 → Qdrant
- Qdrant collection schema 冻结（payload：`chapter_id`、`topic_tags`、`heading`、`chunk_index`）
- `kb_search` 内部换成「向量 top-10 × 0.7 + BM25 × 0.3 → 重排 top-5 → 相邻块拼接」
- `docker-compose.dev.yml`：Qdrant + PostgreSQL + Redis 一键起
- 检索质量基线报告（20 个真实问题的召回情况）

### 按角色的任务

| 角色 | 任务 | 验收 |
|------|------|------|
| R3（主） | Qdrant schema、嵌入模型选型（BGE-M3 本地 / Qwen text-embedding-v3 API）、混合检索实现 | 20 问召回率 ≥ 80%；相同问题两次检索结果稳定 |
| R5（主） | 入库 pipeline、Docker Compose、切分脚本、入库可重跑（幂等） | 全组 `docker compose up -d` 后 `/api/health` 显示知识库片段数 |
| R1 | 教材获取与合规确认；切分粒度评审（公式不能被切断） | 抽查 20 个 chunk，公式完整率 100% |
| R2 | 检索失败时的降级路径（Rethlas 的"检索/非检索交替"） | 连续两次检索无新信息 → 切换纯推理，不死循环 |
| R4 | 前端展示检索来源与相似度；无结果时的友好提示 | 每个回答下方可展开"引用了教材哪几段" |

### 关键设计（必须坚持）
1. **公式永远保留 LaTeX 原文**，不转图片、不转纯文本，否则检索必然失真。
2. **BM25 兜底**：向量对 `E[X]`、`\sigma^2` 这类符号很弱，关键词检索补上。
3. **入库幂等**：改一次切分参数就要重跑全量，脚本必须能安全重跑。
4. **切片不跨公式**：切分前先保护 `$$...$$` 块，避免把公式劈成两半。

### 验收标准
- 20 个覆盖 ch01–ch05 的真实问题：命中正确章节 ≥ 16 个
- `kb_search` 返回的 chunk 里公式完整（人工抽查）
- 换实现后 `smoke_test.py` 全绿（Agent 一行未改 —— 这就是接缝的价值）

### 风险
| 风险 | 应对 |
|------|------|
| Docker 在组员机器上跑不起来 | 保留本地文件检索作为 fallback（`KB_BACKEND=local\|qdrant` 配置开关） |
| 嵌入模型 API 限流/贵 | 优先 BGE-M3 本地推理；API 仅作备选 |
| 切分把公式切断导致检索失真 | 切分前保护公式块；入库后自动抽检公式完整性 |
| 进度超期 | 允许先只入库 ch01–ch05（覆盖 60%+ 考点），剩余章节后续增量入库 |

## P3 · 质量闭环：批改 + 错题库 + 多解对比（3 周）

**目标**：把「生成/验证分权」从"校验"升级为**真正能用的批改闭环**，
这是本项目区别于普通聊天机器人的核心（架构重构建议的 P0）。

### 交付物
- **Grader 多步批改**：接收学生作答 → 逐步判定"对/错/需注意" → 定位首个错误步骤
- **易错点规则库**：从具体错误提炼**跨题目通用规则**（不是"这道题的提示"）
- **经典例题多解对比**：每章 ≥ 2 道例题，每道 ≥ 2 种解法且结果一致
- **HITL 反馈回流**：`feedback` 表记录（原始草稿 + 用户操作 + 最终结论）三元组
- 前端：逐步骤批改视图、错题本页

### 按角色的任务

| 角色 | 任务 | 验收 |
|------|------|------|
| R2（主） | Grader 多步批改节点；验证不通过回环重试（≤ 2 次）后再触发 HITL；多解对比生成 | 10 道预备测试题批改正确率 ≥ 90%；两解结果一致性校验通过 |
| R4（主） | 错题库表结构、逐步骤批改 UI、错题本页 | 完整走通"做题→批改→入库→复习" |
| R3 | 批改环节的 SymPy 数值复核（数值答案必须机器验算） | 所有含数值的批改结论都有 SymPy 佐证 |
| R1 | 例题内容组织与质量把关（多解对比的编排规范） | 每章 2 道例题通过组内评审 |
| R5 | 反馈数据质量评估夹具；E2E 用例扩充到 10 条 | CI 通过率 ≥ 90% |

### 关键设计
1. **批改结论必须"有据可依"**：每一步要么引用教材片段，要么有 SymPy 验算，二者至少有其一。
2. **HITL 交互顺序**：先走「生成→验证」内部闭环，重试 ≤ 2 次仍不通过，才打断用户。
   频繁打断会毁掉体验（架构重构建议 §1.4 闭环四）。
3. **易错点要通用化**：存"假设对象存在时检查是否已构造"（通用规则），
   而不是存"这道题忘了讨论 $x=0$"（个例）。

### 验收标准
- 预备 10 道测试题：批改正确率 ≥ 90%
- 抽查 5 道例题：多解均存在且结果一致
- `feedback` 表有 ≥ 30 条真实交互记录
- 错题库能按知识点聚合，并在学习数据页展示

### 风险
| 风险 | 应对 |
|------|------|
| **LLM 批改概率题的正确率不足** | 这是本阶段最大不确定性。**第一周就做专项验证**：拿 20 道题测批改准确率，< 80% 则调整策略（SymPy 先算、LLM 只做步骤归因），必要时降级为"只标不判" |
| 多解对比生成两种解法但结果不一致 | Verifier 用 `math_check` 做等价性校验，不一致则重试/标记 |
| 反馈数据太少无法形成飞轮 | demo 阶段不追求量，先把**结构**和**回流路径**打通 |

## 四、成本控制

多 Agent 的单次问答 LLM 调用次数天然比单 Agent 多，必须主动控制。

| 措施 | 说明 | 预计节省 |
|------|------|---------|
| 规则优先路由 | 不命中才调 LLM 分类 | 每次问答省 1 次调用 |
| 本地能算的不问模型 | 分布性质走 SymPy，零 LLM | 可视化请求省 100% |
| 验证/批改用轻量模型 | 生成用强模型，验证可降档 | 约 30% 总成本 |
| `agent.delta` 不做二次调用 | 流式本身就是那一次调用 | — |
| Mock 模式跑 CI 与开发 | 只有验收演示才用真模型 | CI 成本为 0 |
| 步骤数上限 | Grader 多步验证限制步数 | 防止长题爆炸 |

**预估**（参考主计划附录 C）：单次完整问答约 8–15 次调用；
用 mock 开发 + 只在演示/评估时用真模型，一个小型项目的预算完全够用。

## 六、演示脚本（答辩 5 分钟版）

> 这个脚本专门为"让评审一眼看出与普通聊天机器人的区别"设计。
> **关键：全程在一个看起来像真实课程平台的页面上操作**，不要打开我们自己的网站。

**0:00–0:30 · 定位**
「我们做的不是一个学习网站，而是一个**能挂到任意在线课程页面上**的伴学助手。
它读得懂学生正在看的这一页。」

**0:30–2:00 · 它真的读懂了这一页（工作台 → 课程页）**
- 打开课程课件页，右下角的页宠出现
- 指着面板顶部的上下文条：`已读取《1.4 全概率公式与贝叶斯公式》、5,171 字、13 个公式、视频 5:18`
- 展开"页面结构"，看到本节大纲
- **在正文里划选一句话** → 悬浮球旁冒出「💡 解释这段」→ 点击
- 观察：页宠变"思考"，协作轨迹里 Orchestrator 判定为 `explain_selection`，
  理由写着「检测到你在页面上划选了 31 字，优先解释选中的内容」
- **一句话点题**：「它知道'这段'是哪段。这是通用聊天机器人做不到的。」

**2:00–3:00 · 视频进度与页内检索**
- 问「我学到哪了」→ 回答里带上视频看到第 5 分 18 秒
- 问「这一页的例题为什么乙线后验概率最大」→ 回答紧扣本页例题的数字（25%/35%/40%）
- 说明：「它先在本页检索，页内没有依据才回退教材知识库，并且会标注来源。」

**3:00–4:00 · 生成/验证分权 + 人机协同**
- 贴一道新题 → `solver` 出步骤 → **黄色 HITL 卡片出现**，页宠变"待确认"表情
- 说明：「解题是关键结论，系统不盲信模型，Verifier 独立复核后暂停等人确认。」
- 点「✏️ 按我的修正重写」，写一句 → 观察**从断点续跑**，最终答案含修正
- **点题**：「修正不重跑整图，回流进最终结论，并写入反馈库。」

**4:00–4:40 · 数学正确性与交互动画**
- 产物里点「打开动画演示」→ 全屏播放既有动画，演示播放/单步/重置
- 切到分布可视化，拖动参数滑块，公式与图像实时更新
- 说明：「公式与数值全部来自 SymPy 符号推导，不是模型生成的。」

**4:40–5:00 · 工程与可扩展性**
- 切到「架构与分工」页：实时 Agent 清单、事件契约、扩展点
- 说明：「新增一个 Agent 只需加一个文件，不改任何共享文件；
  接入新动画只改 manifest.json；支持新平台只改油猴脚本的一行 `@match`。
  这是 5 人并行开发不冲突的原因。」
- 收尾：「断网、无 API Key 时也能完整演示（Mock 模式）；支持自建站一行嵌入，
  也支持超星这类改不了源码的第三方平台。」

**演示前的自检（务必）**
- [ ] 后端已启动，`/api/health` 正常
- [ ] 浏览器已装油猴脚本（或演示页用 loader.js）
- [ ] **拔网线演练一遍 Mock 模式**（防止现场网络故障）
- [ ] 页宠不被浏览器缩放挡住，字体大小是 100%
