## 一、第一次跑起来（15 分钟，别跳）

```powershell
git clone <仓库地址>
cd ProbCrew
.\启动.bat                      # Linux/macOS 用 bash start.sh
```

**不需要** `npm install`、打包、Docker 或 API Key。
没配 `DEEPSEEK_API_KEY` 会自动降级 **mock 模式**（假模型，离线可跑，不花钱）。

启动后控制台会打印真实地址，然后打开**这个**：

| 想试什么 | 地址 | 注意 |
|---|---|---|
| **原始动画 + 悬浮窗**（推荐先试） | `/raw-live/` | 后端在响应时注入悬浮窗 |
| 演示课程页 | `/course/` | 模拟真实课程平台 |
| 独立站点外壳 | `/` | 工作台 / 动画库 / 分布可视化 |

> ⚠️ **`/raw/` 和 `/raw-live/` 不是一回事**：
> `/raw-live/` **有**悬浮窗，`/raw/` 只是同一批动画的静态文件、**没有**悬浮窗。
> 想试助手就开 `/raw-live/`。

**语义检索（可选）**：想用真正的向量检索，需要先拉本地权重（约 4.5 GB，装一次）：

```powershell
python scripts/setup_models.py
```

不装也能跑：向量层会**如实标注**已降级，不会假装在做语义检索。

### 第 2 步 · 把那张卡读全

每张卡有固定的 8 个字段。**开工前确认你知道了这四样**：

| 字段 | 为什么必须确认 |
|---|---|
| **写入范围** | 你**只能**改这些文件。改别的会和人撞 |
| **禁止触碰** | 明确不能碰的文件（通常是别人的独占文件） |
| **接口冻结** | 本任务**不许**改的契约 —— 想改要先走 ADR |
| **验收** | 一张卡对应**一条能跑的命令** + 期望输出。这就是你的 DoD |

**分支命名**：`feat/<任务ID>-<简述>` · `fix/<任务ID>-<简述>` · `docs/<简述>` · `ci/<简述>`

提交前**把卡片"验收"那一节的每条命令都真跑一遍**，输出贴进 PR 描述。

## 四、避冲突：这是并行开发不打架的关键

### 4.1 架构天生抗冲突

本项目用**自动发现**替代了传统的"注册表"，所以你加东西**不需要改公共文件**：

```
app/agents/*.py   →  discover_agents()   →  AgentRegistry
app/tools/*.py    →  discover_tools()    →  ToolRegistry
app/api/*.py      →  discover_routers()  →  FastAPI include_router
features/*/       →  gen_registry.py     →  features.registry.js
```

| 想加什么 | 放哪 | **不需要**改 |
|---|---|---|
| Agent | `backend/app/agents/<名字>.py` | `graph.py`、`__init__.py`、注册表 |
| 工具 | `backend/app/tools/<名字>.py` | 任何注册文件 |
| 接口 | `backend/app/api/<名字>.py` | `main.py` |
| 页面 | `frontend/app/features/<名字>/` | `index.html`、`bootstrap.js` |
| 投递方式 | 只写交付层 | **`extractor.js` 与后端**（架构红线） |

### 4.2 少数共享文件由任务独占

`docs/17` §四 有一张完整表。**开工前对照一遍**，最常撞的三个：

| 共享文件 | 谁独占 | 你要改怎么办 |
|---|---|---|
| `backend/app/kernel/specs.py` | **K1 → K2**（串行） | 提 PR 说明，等 K2 合完 |
| `backend/app/agents/_router.py` | **K3** | 改动形态是"加一个 key"，但要提 PR 说明 |
| `frontend/app/components/trace.js` | **X1** | K2 只改后端，不动前端 |

**规则**：PR 的 diff 应集中在你自己的目录里。**必须**碰共享文件时，在 PR 描述里**单独列出并说明原因**。

### 4.3 三条最容易被违反的纪律

1. **契约只增不改**：改字段名/改语义/删枚举 **都是破坏性变更**，必须走 ADR。
   新增事件类型要**同时**改三处：`events.py` + `events.schema.json` + `contracts/CHANGELOG.md`
2. **失败必须显式**：读不到内容 / 检索为空 / 校验不过 —— 都要**说出来**，**不允许沉默降级**
3. **别把模型当计算器**：能用 SymPy 或规则判断的，不要交给 LLM

## 五、Git 流程（踩过坑，照做）

```
feature/xxx ──squash──▶ dev ──merge（★ 绝不 squash）──▶ main
```

| 方向 | 用什么 | 为什么 |
|---|---|---|
| `feature → dev` | `--squash` | 一个特性一个提交 |
| `dev → main` | `--merge` | ★ squash 会让 `dev` 与 `main` **历史分叉**，之后 `merge --ff-only` 全失败 |

**记住这句话**：`squash` 只能用在"合并后分支就删掉"的场合。
`dev` 是长期分支，**永远不要 squash 合它**。

**不要提交**：`.env`、`backend/data/*.sqlite`、`__pycache__`、大文件教材原始 PDF、任何学生数据。

## 七、遇到这些情况怎么办

| 情况 | 怎么办 |
|---|---|
| 三条自检命令不绿 | **先问**，别改代码 —— 可能是环境问题 |
| 任务卡的"现状证据"对不上 | **先怀疑文档过期**（按 `docs/17` §七 自己复测），确认后**更新那张卡** |
| 想改的文件不在我的写入范围 | 在 PR 描述里说明，或找那张卡的负责人协调；**别偷偷改** |
| 想改契约（加字段/改语义） | 先在群里说 → R1 确认 → 走 `docs/adr/` → 再写代码 |
| 发现文档写错了 | 记到 `docs/18` §四 的漂移表里（G2 任务负责收敛），**别顺手改一堆数字** |
| 拿不到外部资源 | 教材（D3）、智慧树账号（D2）—— 这两件**不占技术排期**，先做别的 |
