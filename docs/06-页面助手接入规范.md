# 06 · 页面助手接入规范

> 本文档描述**产品的最终形态**：一个可以注入到在线课程页面上、
> 能读懂学生正在看什么的 AI 伴学助手（悬浮球 / 虚拟页宠）。
>
> 前置阅读：`01-架构总览.md`（内核）、`02-事件契约.md`（事件协议）。

---

## 1. 产品形态

**不是**一个独立的学习网站，**是**一个挂在别人课程页面上的助手。

```
┌─────────────────────────────────────────────────────────┐
│  在线课程平台（超星 / 智慧树 / 自建站）                    │
│  ┌───────────────────────────────────┐                  │
│  │  课件正文（可能在 iframe 里）        │   ┌──────────┐  │
│  │  标题 / 段落 / 公式 / 选中文字       │   │ 🐾 页宠   │  │
│  │  <video> 视频进度                   │   │  （悬浮） │  │
│  └───────────────────────────────────┘   └────┬─────┘  │
└────────────────────────────────────────────────┼────────┘
        ▲ 抽取页面上下文                          │ 提问
        │                                        ▼
   ┌────┴─────────────────────────────────────────────┐
   │  our-system 后端（LangGraph 多 Agent 协作）        │
   │  Orchestrator → Page Tutor / Knowledge / Solver…  │
   └──────────────────────────────────────────────────┘
```

**核心差异点**：普通聊天机器人不知道"这段"是哪段；本助手知道。
它能看到正文、标题层级、公式、学生划选的文字、视频看到第几秒、甚至正在操作的动画停在第几步。

## 2. 三套投递方式

| | ① 免安装试用 | ② 自建站 / 演示页 | ③ 第三方平台（超星等） |
|---|---|---|---|
| **方式** | `/raw-live/` 后端动态注入 | 一行 `<script>` | 油猴脚本注入 |
| **文件** | 无需任何文件 | `widget/loader.js` | `widget/probstat-assistant.user.js` |
| **适用** | 团队原始动画文件夹，想立刻看到效果 | 自己控制的课程站 | 改不了源码的平台 |
| **改代码后** | 刷新即生效 | 刷新即生效 | 需在 Tampermonkey 里"检查更新" |
| **CSP 风险** | 无 | 无 | 用 `@require` 规避 |

### 2.0 免安装试用：`/raw-live/`（推荐从这里开始）

团队原始的动画文件夹在 `大创/动画`，有 8 个动画 + 1 个导航页。
**我们一个字节都不改它们**（它们要能离线、能单独分发、能塞进数字教材）。

后端提供了一条镜像路由，在**响应的最后一刻**把 loader 注入到 `</body>` 前面：

```
/raw/贝叶斯公式(g).html         →  原始文件，原封不动
/raw-live/贝叶斯公式(g).html    →  同一个文件 + 悬浮窗
```

于是有了一个"带悬浮窗的完整镜像"：

```
http://127.0.0.1:8000/raw-live/                    ← 动画导航页 + 页宠
http://127.0.0.1:8000/raw-live/贝叶斯公式(g).html    ← 任意单个动画 + 页宠
```

好处：
- **零安装**：不用装 Tampermonkey、不用改文件；
- **同源**：跟后端同一个 origin，跨域问题彻底消失，动画可读可控；
- **原文件干净**：磁盘上的时间戳不会变（可以用 `scripts/` 里的检查确认）；
- 导航页里的相对链接（`./贝叶斯公式(g).html`）会自动解析到 `/raw-live/...`，
  所以整个文件夹在这个路径下就是一个完整镜像。

实现见 `backend/app/api/raw_live.py`。它做了路径穿越防护（只取文件名最后一段 +
解析后校验仍在基目录内），并只处理 `.html`。

> 为什么不能直接双击 `动画/*.html`？
> `file://` 下浏览器把页面视为 **opaque origin**：跨域请求被拒（调不通后端），
> iframe 的 `contentDocument` 也读不到。悬浮窗在 `file://` 下等于废掉。
> 换成 `http://127.0.0.1:8000/raw-live/...` 一次性解决。

### 2.1 自建站：一行代码

```html
<script src="https://your-host/widget/loader.js"
        data-api="https://your-host"
        data-auto-open="false"
        data-skin="pet"></script>
```

| 属性 | 说明 |
|------|------|
| `data-api` | 后端地址。省略 = 与脚本同源（推荐） |
| `data-auto-open` | `"true"` 进页面就展开面板 |
| `data-skin` | `pet`（虚拟页宠，默认）/ `ball`（极简悬浮球） |

### 2.2 第三方平台：油猴脚本

1. 浏览器安装 **Tampermonkey**（或 Violentmonkey）。
2. **先启动后端**（`.\scripts\dev.ps1`），否则 `@require` 拉不到模块。
3. 打开 `http://127.0.0.1:8000/widget/probstat-assistant.user.js`，
   Tampermonkey 会自动弹出安装页；或新建脚本、粘贴内容。
4. 修改脚本里的 `API_BASE` 为你的后端地址（部署后）。
5. 打开课程页面 → 右下角出现页宠。

**建议收窄 `@match`**：脚本默认 `*://*/*`（方便试用），
正式使用请改成只在需要的平台运行，省内存也避免打扰：

```js
// @match  *://*.chaoxing.com/*
// @match  *://*.icourse163.org/*
// @match  *://*.zhihuishu.com/*
```

```
http://127.0.0.1:8000/course/
```

这是一个模拟真实课程平台的课件页（1.4 全概率公式与贝叶斯公式），

## 3. 页面上下文抽取

实现：`frontend/widget/extractor.js`。

### 3.1 抽取策略（按可靠性排序）

1. **显式提示**：`#lesson-content`、`[data-lesson-content]`、`article`、`main`、
   `[role=main]`、`.course-content`、`.markdown-body` 等（要求正文 ≥ 300 字）
2. **阅读密度打分**（仿 readability 轻量版）：遍历候选容器，按
   `Σ(段落长度) × (1 − 链接密度)` 排序，取最高分
3. **兜底**：`document.body`

对选中的容器：剥离 `script/style/nav/header/footer/aside/iframe/.sidebar/.toc/...`
→ 按块级元素还原段落 → 收集标题与公式。

### 3.2 抽取的数据结构

```jsonc
{
  "url": "https://mooc.example.edu/courseware/ch01-4.html",
  "title": "1.4 全概率公式与贝叶斯公式",
  "headings": [{ "level": 1, "text": "1.4 全概率公式与贝叶斯公式" }, ...],
  "text": "设 B1,B2,...,Bn 为完备事件组……",   // 上限 12000 字
  "selection": "贝叶斯公式则是在已知 A 发生的条件下……",  // 上限 3000 字
  "formulas": ["P(A)=\\sum_{i=1}^{n}P(B_i)P(A\\mid B_i)", ...],
  "media": { "kind": "video", "currentTime": 318, "duration": 900, "title": "……" },
  "animation": { "id": "bayes", "title": "贝叶斯公式", "state": "已暂停" },
  "scroll_pct": 0.42,
  "score": 5171
}
```

**公式过滤**：只上报"像公式的"内容。
课件里到处是 `$A$`、`$B$`、`$i$`，全部收进来会把有用信息淹掉
（`to_prompt()` 只展示前 12 条）。独立公式块 `$$...$$` 全部保留；
行内公式需满足「长度 ≥ 6 且含 `\命令`／`=`／上下标／数字运算」才保留。

### 3.3 跨 iframe 汇总（这是最关键的一层）

**问题**：超星、智慧树这类平台的课件大量嵌套在 iframe 里，正文往往**不在顶层**。
顶层只是一个导航壳。浏览器不允许顶层脚本读取跨域 iframe 的 DOM。

**解法**：油猴脚本在所有 frame 各注入一份，用 `postMessage` 上报。

```
顶层 frame                          子 frame（课件）        孙 frame
─────────                          ──────────────         ────────
collectAll()
  ├─ 自己抽取 ──────────┐
  ├─ postMessage ──────►├─ 自己抽取 ──┐
  │  (request)          └─ postMessage ►├─ 自己抽取
  │                        (request)   └─ 回传
  │◄──── 回传 frames[] ─────────────────┘
  └─ 按 score 归并 → 主上下文
```

- **递归**：子 frame 被请求时也会先问自己的孩子，整棵树都覆盖到。
- **归并**：后端 `merge_frames()` 选内容丰富度最高的那一帧作为主上下文
  （真实场景下就是装着课件的那个 iframe），其余作为补充检索源。
- **选中文字**：可能出现在任意 frame，归并时优先取非空的那一份。
- **只在顶层渲染 UI**：否则每个 iframe 都会冒出一个悬浮球（超星一页能有十几个 frame）。
- **安全性**：跨域只能用 `targetOrigin='*'`，靠私有 magic key 识别，
  且**只回传给发消息的 `event.source`**，不广播。只传页面公开可见的文本，
  不涉及 cookie / 凭证。

### 3.4 用户可见性

助手必须在面板顶部明确显示"我读到了什么"，否则用户不知道它是否理解了自己指的是哪段：

```
📄 已读取 《1.4 全概率公式与贝叶斯公式》、5,171 字、2 个公式、已选中 31 字、视频 5:18、2 个框架
   展开页面结构 ▾
```

读不到时显示警告（黄色），而不是沉默：
```
⚠️ 这个页面读不到正文（可能是空页或内容在跨域框架里）
```

标题栏的 **📖 按钮**可以关闭页面读取（隐私考虑），关闭后：
- 不再抽取、不再上报；
- 快捷问题切换为通用的教材问题；
- 后端收到 `chars: 0`，只用知识库回答。

## 4. 后端契约

### 4.1 请求

`POST /api/chat/stream` 新增可选字段 `page_context`：

```jsonc
{
  "query": "这段什么意思？",
  "session_id": "web_ab12cd34",
  "page_context": {
    "source": "userscript",          // userscript | widget | api | spa
    "selection": "……",                // 顶层页面的选中文字（可选）
    "frames": [ /* 上面 3.2 的结构，可多份 */ ]
  }
}
```

后端 `kernel/page_context.py::from_payload()` 负责解析：
- 有 `frames` → `merge_frames()` 归并；
- 没有 `frames` → 当作单帧处理（简单调用方只需传 `{"text": "...", "selection": "..."}`）；
- **解析失败返回 `None`，绝不抛异常** —— 上下文问题不能阻塞提问。

### 4.2 新增事件 `context.received`

在 `run.start` 之后立即发出，让用户**看得见助手读到了什么**：

```jsonc
{
  "type": "context.received",
  "run_id": "run_ab12",
  "summary": "已读取 《1.4 全概率公式与贝叶斯公式》、259 字、2 个公式、已选中 31 字、含视频进度、跨 2 个框架",
  "data": {
    "title": "1.4 全概率公式与贝叶斯公式",
    "chars": 259, "selection_chars": 31, "formula_count": 2,
    "frame_count": 2, "has_media": true, "animation": null,
    "outline": "- 1.4 全概率公式与贝叶斯公式\n  - 全概率公式\n  - 贝叶斯公式"
  }
}
```

**只在调用方提供了 `page_context` 时才发**。
纯 API 调用方（SPA、脚本）不传这个字段，就不会收到这条噪音事件。
发出位置在 `kernel/runner.py::_emit_context()` —— 放在 runner 而非 HTTP 层，
是为了让任何传输方式（HTTP / CLI / 测试）行为一致。

### 4.3 新增 Agent：`page_tutor`（Page Tutor 页面伴学）

| 项 | 值 |
|---|---|
| id | `page_tutor` |
| 名称 | Page Tutor 页面伴学 |
| 角色 | generator |
| 工具 | `page_search` / `page_outline` / `page_selection` / `kb_search`（角色门控） |
| 产出 | `formula` / `table` / `text` |
| 意图 | `explain_page` / `explain_selection` |

**三种工作模式**：

| 模式 | 触发 | 行为 |
|------|------|------|
| `selection` | 有划选文字且在问"这是什么意思" | 直接解释选中那段，补上跳过的推导步骤 |
| `progress` | 问"我学到哪了 / 进度" | 报告章节位置 + 视频进度 + 滚动位置 |
| `explain` | 其他页面问题 | **先页内检索**（`page_search`），页内没有依据才回退教材知识库 |

**检索策略：先页内，后教材。** 学生问的是眼前的东西，答案首先该来自那一页。

### 4.4 路由规则（`agents/_router.py`）

页面上下文改变了路由优先级：

```
1. 有划选文字 + 在问"什么意思"（或问题 ≤ 12 字）
      → explain_selection   "检测到你在页面上划选了 31 字，优先解释选中的内容"
2. 问题里明确指代"当前页面"（这一页/这段/本节/课件/视频/…）
      → explain_page        "问的是当前页面的内容，交给页面伴学"
3. 命中教材类特征词（求解/画图/进度…）
      → 原来的行为，不变
4. 什么都没命中，但正在看课程页
      → explain_page        "未命中教材类特征词，按当前页面问题处理"
      （这是伴学助手该有的默认行为：坐在旁边，随时接住问题）
```

**明确的解题意图仍然优先**：`求解：已知 P(B1)=0.5…` 依旧走 `solver`，
页面上下文不会吞掉明确意图（有单元测试守着这条）。

## 5. 形象系统

实现：`frontend/widget/pet.js`。Canvas 自绘，零依赖。

### 5.0 动画页面模式（`anim-bridge.js`）

当悬浮窗被注入到**动画页面自身**时，它进入"动画模式"，这是能力最强的场景：

| | 助手在父页面（iframe 里） | 助手在**动画页面自身** |
|---|---|---|
| 读内容 | 隔着 iframe，需同源 | 直接读，零障碍 |
| 驱动动画 | `contentDocument.querySelector('#playBtn').click()` | 直接 `document.querySelector(...).click()` |
| 知道学生操作到哪 | 只能靠 adapter 上报 | 监听点击，实时知道"已单步 3 次" |

检测方式（`animBridge.detect()`）：
1. 页面上能同时找到 ≥3 个控制按钮（`#playBtn`/`#startBtn`、`#pauseBtn`、`#stepBtn`、`#resetBtn`），或
2. 有 `<canvas>` 且至少 1 个控制按钮

再用**文件名**去 `/api/animations` 的清单里匹配（归一化 Unicode 与空格，并容忍 `(g)` 后缀差异），
拿到动画 id、标题与知识点。

进入动画模式后，面板会：

- 标题变成 `伴学 · 贝叶斯公式`
- 顶部多出一条**动画控制条**（▶ ⏸ ⏭ ⟲ + 当前状态），学生不用在页面和面板间来回找按钮
- 快捷动作换成动画专属的四条，其中最重要的一条是：

**「⏭ 单步并讲解」** —— 助手先替学生把动画往前推一步，再针对"刚发生的变化"提问：

> 「我刚才把动画单步推进到了第 3 步。请告诉我：这一步在演示什么？
> 和上一步相比发生了什么变化？为什么这个变化在概率论上是重要的？」

这样模型的回答是针对**具体现象**的，而不是泛泛介绍知识点。
实测（真模型）它能读出页面上的「在证据 B 下的更新信念」与 `P(A|B)=63.2%` 并据此讲解。

学生自己点动画按钮时，捕获阶段的监听会同步更新状态，
所以面板里的"已单步 N 次"始终是真实的。

### 5.1 两套皮肤

| 皮肤 | 说明 |
|------|------|
| `pet` | 虚拟页宠：会眨眼、会浮动、有触角发光点，随状态变表情 |
| `ball` | 极简悬浮球：渐变球 + 呼吸感 + 状态色脉冲 + 中央 π |

用户可在面板标题栏用 **🎭 按钮**随时切换，选择记在 `localStorage`。

### 5.2 状态机 —— 由**真实 Agent 事件**驱动

| 状态 | 触发事件 | 表现 |
|------|---------|------|
| `idle` | 无任务 | 微笑、缓慢浮动 |
| `thinking` | `run.start` / `agent.start` / `plan` | 眼睛上瞟、头顶飘思考点、触角发亮 |
| `talking` | `agent.delta` | 嘴巴随 token 流开合 |
| `happy` | `artifact` / `run.end` | 眯眼笑、腮红、闪光 |
| `alert` | `hitl.request` | 眼睛睁大、头顶"!"（同时悬浮球显示红色角标） |
| `sad` | `error` | 撇嘴、状态色转红 |
| `sleeping` | 90 秒无操作 | 闭眼弧线、飘 "z" |
| `offline` | 健康检查失败 | 灰色、状态栏提示"后端未连接" |

**这不是装饰**。学生不用看日志，看表情就知道系统在干什么、是否需要自己出面。
这是答辩演示时最直观的一环。

### 5.3 实现注意（踩过的坑）

- **rAF 循环必须可停**：本项目里 `马尔科夫链 (g).html` 的教训 —— 闭包里跑着停不掉的
  `requestAnimationFrame`，页面切走后一直烧 CPU。`destroy()` 会真的 `cancelAnimationFrame`。
- **页面不可见时暂停**：监听 `visibilitychange`，避免后台标签页空烧。
- **高分屏缩放**：按 `devicePixelRatio` 设置 canvas 位图尺寸，否则边缘发虚。
- **尊重 `prefers-reduced-motion`**：CSS 里已关闭面板与胶囊的动画。

## 6. 在真实平台上要注意的事

| 问题 | 现象 | 处理 |
|------|------|------|
| **CSP 拦截** | 悬浮球根本不出现，控制台有 CSP 报错 | 改用油猴的 `@require` 方式（安装时抓取，运行时不受站点 CSP 限制） |
| **跨域 iframe** | 读不到课件正文，上下文条显示"读不到正文" | 这是设计内的降级；依靠"所有 frame 都注入 + postMessage 上报"覆盖。若平台连 iframe 都不让注入，则只能读到顶层 |
| **平台自身弹层很高** | 悬浮球被盖住 | 助手 `z-index: 2147483000`，已高于绝大多数平台 |
| **平台禁用 localStorage** | 皮肤/位置/会话不记忆 | 全部 `try/catch` 包裹，降级为不记忆，不报错 |
| **平台样式污染** | 助手变丑 / 平台被助手搞乱 | 助手全部关在 **Shadow DOM** 里（双向隔离）；KaTeX 的 CSS 也必须注入 Shadow Root 内部，否则公式渲染成裸 HTML |
| **SPA 切章节不刷新** | 上下文停留在上一节 | `MutationObserver` 监听 DOM 变化，1.2 秒后重算上下文 |
| **CPU 占用** | 风扇响 | 头像 rAF 在后台标签页暂停；交互动画 iframe 关闭时**销毁节点**而不是隐藏 |

## 7. 已知限制（诚实清单）

1. **跨域 iframe 里没装脚本就读不到**。我们依赖"所有 frame 都被注入"。
   如果某个平台把课件放在第三方域的 iframe 里且油猴的 `@match` 没覆盖到那个域，
   那一帧的内容会缺失（其余 frame 仍可用）。
2. **视频进度只在能读到 `<video>` 元素时有效**。若播放器是自定义 Canvas/Flash 实现，
   读不到 `currentTime`，此时只报告"这是视频页"。
3. **`@require` 方式下改代码需重新同步脚本**。开发期请用演示课程页
   （`/course/`，走 `loader.js`，刷新即生效）。
4. **没有做题/测验交互**。当前只做"看与问"，不做"练与判"（那是 P3 阶段的工作）。
5. **没有用户体系**。会话 id 存在浏览器本地，任何人可伪造；上生产必须换 JWT。
6. **`page_search` 是词重叠打分，不是向量检索**。与 `kb_search` 同样的接缝，
   后续可换成嵌入检索（接口不变）。
7. **未在真实超星账号上验证过**。演示页是仿造的；真机验证需要课程账号，
   属于 P1 阶段的必修项（见开发计划）。
