> 变成「系统对学生有**持续、可量化的认识**，老师能**看见并干预**」。

## 一、为什么 B线也是"硬"的

我在选方向时用过三条判据（有唯一判据 / 需要搜索试错 / 能度量提升）。
B线乍看像"教育产品"，其实三条都满足 —— 关键在于**教育测量学是一门有百年积累的定量学科**，
而且有**公开基准数据集**可以对标。

| 判据 | B线怎么满足 |
|------|------------|
| **有唯一正确答案** | 教育测量模型的实现可以在公开数据集上对标。ASSISTments / EdNet 是标准基准，文献报告的 BKT 预测 AUC 大致在 0.67–0.80 区间 —— **我们的实现达不到就是错的**，这不是"感觉好不好"的问题 |
| **需要搜索/试错** | 掌握度是隐变量，要用 EM / MCMC 拟合；题目难度与学生能力要**联合估计**（鸡生蛋问题）；复习调度是**序贯决策**问题 |
| **能度量提升** | 离线：预测学生下一次作答的 AUC / RMSE / 校准度。在线：A/B 对比"按模型调度复习"vs"不调度"的知识保持率 |

**这是 B线比 A线（可验证数学推理）更被低估的地方**：
A线的"对错"要靠自己定义，B线的"对错"有公开基准和文献区间可以直接比。

## 二、系统架构：三层 + 一条闭环

```
┌─────────────────────────────────────────────────────────────────┐
│  教师端（Teacher Console）                                        │
│  班级热力图 · 薄弱点聚类 · AI 产出审核 · 组卷 · 学情报告            │
└────────────────────────────┬────────────────────────────────────┘
                             │  ① 看：学情可视  ② 改：审核 AI 产出
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  学习者模型层（Student Model）          ← B线的技术核心            │
│                                                                  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐          │
│  │ 知识图谱 DAG │→│ BKT 掌握度   │→│ 级联诊断      │          │
│  │ 前置依赖     │  │ P(掌握) 概率 │  │ 找薄弱根源    │          │
│  └──────────────┘  └──────────────┘  └──────────────┘          │
│         ↑                  ↑                  ↓                 │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐          │
│  │ IRT 题目标定 │  │ 遗忘模型      │  │ 复习调度      │          │
│  │ 难度/区分度  │  │ FSRS / SM-2  │  │ 今天该复习啥  │          │
│  └──────────────┘  └──────────────┘  └──────────────┘          │
└────────────────────────────┬────────────────────────────────────┘
                             │  ③ 吃：结构化作答事件
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  数据层（P0 前置，必须最先做）                                     │
│  作答事件 · 题目库 · 知识点标注 · 会话记录 · 教师修正               │
└────────────────────────────┬────────────────────────────────────┘
                             │  ④ 反哺：修正回流改进生成
                             ▲
┌─────────────────────────────────────────────────────────────────┐
│  现有系统（7 Agent / LangGraph / 页面助手）                        │
│  知识点讲解 · 题目讲解 · 分布可视化 · 页面伴学                      │
│  ← P0 在这里加"做题 / 提交 / 批改"闭环                            │
└─────────────────────────────────────────────────────────────────┘
```

**闭环的关键**：教师端的「审核修正」不是锦上添花，它是**数据飞轮的入口**。
现在 HITL 的用户修正**只写进 SQLite 就没人看了** —— 这是现有系统最可惜的地方。B线要把它接回生成流程。

## 三、必须先正面回答的四个设计问题

这四个问题不回答清楚，后面全是返工。

### Q1：数据从哪来？（→ 决定 P0 做什么）

**现状：一条做题数据都没有。** 现在只有"问答记录"，没有"这位学生在哪个知识点上答对了/错了"。

所以 B线的**第一个任务不是建模，是造数据**：

```
学生在页面上做题 → 提交答案 → 系统批改 → 落成结构化事件
```

**结构化事件是本项目的核心数据资产**，schema 必须先冻结：

| 字段 | 说明 | 为什么需要 |
|------|------|-----------|
| `student_id` | 假名化 ID（不是学号！） | 隐私 |
| `item_id` | 题目 ID | 关联 IRT 难度 |
| `kc_ids[]` | 这道题考的知识点（可多个） | BKT 按知识点建模型 |
| `correct` | 是否答对 | 观测值 |
| `answer_raw` | 原始作答 | 错误分析 |
| `hint_used` | 是否用了提示 | 区分"独立答对"与"被提示后答对" |
| `duration_ms` | 耗时 | 区分"会但慢"与"猜" |
| `attempt_no` | 第几次做这道题 | BKT 的学习效应 |
| `source` | `practice` / `exam` / `self` | 数据质量分层 |
| `created_at` | 时间戳 | 遗忘模型要 |

> ⚠️ `hint_used` 和 `duration_ms` 是**容易被忽略但极有价值**的两个字段。
> "没提示、若干时间、答对"和"用了 3 次提示、5 分钟、答对"在掌握度上完全不同 ——
> 少了这两个字段，BKT 会把它们当成同一个观测。

### Q2：冷启动怎么办？（→ 决定 P2 的策略）

BKT/IRT 都需要数据才能拟合。一个新学生、一道新题，什么都没有。

**分三档处理**：

| 阶段 | 数据量 | 策略 |
|------|--------|------|
| 零数据 | 0 | 用**先验**：知识点难度由教师/大纲标注；学生初始掌握度用 0.3 之类的先验 |
| 少量 | 学生 <20 次作答 | 用**全体学生的群体参数**当作个人先验（分层贝叶斯思想） |
| 充足 | >100 次 | 个人参数 EM 拟合 |

**这道工序要写进代码，不能靠"等数据够了再说"** —— 否则系统前几个月是瞎的，没人愿意用。

### Q3：怎么证明模型有用？（→ 决定评估怎么做）

三档评估，从离线到在线：

1. **离线预测**（最容易）：留出学生最后 20% 的作答，用前面的数据预测后面，算 AUC / RMSE / 校准曲线
2. **对标基准**：在我们自己的数据上跑，也在 ASSISTments 公开数据上跑 —— 后者能与文献数字对比
3. **在线 A/B**（最有说服力）：一半学生用模型调度复习，一半按固定顺序做，两周后测保持率

**第 3 条是大创能出彩的地方**：真实的教学效果对比，比任何技术指标都有分量。

### Q4：隐私怎么办？（→ 这是**必答题，不是加分题**）

我在 `原型声明.md` 里写过"不要接入真实学生数据"。**做 B线就意味着必须正面解决它**，否则不能上真实课堂。至少要处理：

| 项 | 做法 |
|----|------|
| **知情同意** | 学生/家长知情同意书；明确告知"哪些数据被收集、用来做什么、发给谁" |
| **数据最小化** | 只收建模必需的字段；不收姓名、学号、身份证 |
| **假名化** | `student_id` 用随机 UUID，映射表与数据分开存放，映射表由教师保管 |
| **第三方边界** | ★ **学生答题数据要不要发给 DeepSeek 批改？** 发出去就出校了 —— 见下 |
| **权限隔离** | 教师只能看自己班；学生只能看自己 |
| **删除权** | 提供"删除我的数据"入口，且是真的删 |
| **优先私有部署** | 生产环境应把 LLM 换成校内私有部署的开源模型 |

**关于第三方边界，有三条路线，必须选一条：**

| 路线 | 优点 | 缺点 |
|------|------|------|
| ① 脱敏后发云端 LLM | 简单，现在就能做 | 作答原文仍外流；合规风险 |
| ② 本地部署开源模型做批改 | 数据不出校 | 需要 GPU；效果可能差些 |
| ③ **只用确定性方法批改** | 数据完全不出校 | 只能批数值/选择题 |
| **④ 混合（推荐）** | 客观题走 ③（数学计算用 SymPy），主观题**脱敏后**走 ① 且**记录审计日志** | 复杂度上升 |

**我推荐 ④**，并且把它作为 P0 的设计约束写进数据层 —— 而不是等做完再补。

## 四、分阶段计划

> 时间单位「周」按 5 人小组、每人每周约 8–10 小时估。
> **P0 是地基，P0 没做完不准开工 P2**（否则模型无米下锅）。

### P0 · 做题与批改闭环 + 数据契约★ 最高优先级

**目标**：让系统产生第一批量化的、结构化的作答数据。

| 交付物 | 说明 |
|--------|------|
| `problems` 题库表 | 从现有 10 道例题扩到 **≥60 道**，每题标注知识点 |
| `attempts` 作答事件表 | 按 Q1 的 schema，字段**冻结** |
| 做题 UI | 页面助手面板里新增"练习"模式；SPA 新增「练习」页 |
| 批改双轨 | 数值题走 SymPy（确定性）；主观题走 LLM + 脱敏 |
| 批改 API | `POST /api/practice/submit` → `{correct, feedback, kc_ids}` |
| 数据契约文档 | `contracts/attempt.schema.json` |

**验收标准**
- [ ] 能完整走通"出题 → 作答 → 批改 → 入库"至少 60 道题
- [ ] `attempts` 表字段齐备，含 `hint_used` / `duration_ms`
- [ ] 数值题的批改 100% 由 SymPy 判定（不经过 LLM）
- [ ] 脱敏管线可验证：日志里搜不到学生姓名/学号
- [ ] 造出 **≥300 条**模拟作答数据（用来跑通后续模型，不必等真实学生）

> 💡 **造模拟数据这件事很重要**：用已知参数生成合成数据（例如设定某学生"真的掌握"了知识点 A），
> 这样 P2 的 BKT 实现**立刻就能验证能不能把参数还原回来**，不必等真实数据。

### P1 · 知识图谱：知识点 DAG

**目标**：把 18 个知识点从"扁平列表"变成"有依赖关系的有向图"。

| 交付物 | 说明 |
|--------|------|
| 知识点 DAG | ~60–100 个知识点节点（比现在 18 个更细），~120 条依赖边 |
| 标注工具 | 一个简单页面：选两个知识点 → 标"前者是后者的前置" |
| 标注一致性校验 | 检测环、检测孤立点、检测矛盾 |
| 可视化 | DAG 图（前端 Canvas 自绘，零依赖） |

**为什么这一步必须先于 BKT**：BKT 是按知识点建模型的 —— 你总得先知道**有哪些知识点**。
现在知识库只有 18 节，粒度太粗（"连续型随机变量"底下藏着期望、方差、密度函数三件事）。

**验收标准**
- [ ] DAG 无环（拓扑排序可跑通）
- [ ] 每个知识点至少关联 1 道题
- [ ] 两名成员独立标注同一批知识点，一致率 ≥ 80%（Kappa 系数）
- [ ] 由指导老师抽查确认依赖关系合理

---

### P2 · BKT 掌握度模型★ 技术核心

**目标**：把"正确率排序表"换成**概率模型**。

**要实现的**：每个知识点一个 BKT 模型，四参数 `(p_L0, p_T, p_S, p_G)`，
用 EM（Baum-Welch）在作答序列上拟合，输出 **P(已掌握)**。

**为什么比正确率强**（这是这一阶段的价值主张）：

| 情形 | 正确率 | BKT |
|------|--------|-----|
| 会，但手滑错了一次 | 50% | P(掌握) ≈ 0.7（识别出是 slip） |
| 不会，但蒙对了 | 50% | P(掌握) ≈ 0.2（识别出是 guess） |
| 练了 5 次全对 | 100% | P(掌握) ≈ 0.97 |
| 一次没练过 | — | P(掌握) = 先验 |

**同样的正确率，BKT 能区分出完全不同的掌握状态** —— 这就是教育测量学的价值。

| 交付物 | 说明 |
|--------|------|
| `domain/bkt.py` | BKT + EM，纯 Python/NumPy，**不依赖第三方库** |
| 合成数据验证 | 用已知参数生成序列 → 检验能否还原参数（误差 < 5%） |
| 公开数据对标 | 在 ASSISTments 上跑，AUC 落在文献区间内 |
| 掌握度 API | `GET /api/students/{id}/mastery` |
| 前端掌握度视图 | 替换学习数据页现在的条形图，改为"P(掌握) + 置信度" |

**验收标准**
- [ ] 合成数据参数还原误差 < 5%
- [ ] 真实/对标数据上，预测下一题正确率的 **AUC ≥ 0.70**
- [ ] 校准曲线合理（预测 0.7 的那批，实际正确率接近 0.7）
- [ ] 冷启动策略生效（新学生也有合理输出，不返回空白）

---

### P3 · 级联诊断：找薄弱根源

**目标**：从"你答错贝叶斯"升级到"**你的根因是全概率公式没掌握**"。

这是现有架构文档里承诺过、但一直没做的 P1 机制。

**算法思路**：给定低掌握度的知识点 $v$，沿 DAG 反向搜索候选前置 $u$，
按 `根源得分 = P(未掌握_u) × 依赖强度(u→v) × 层级距离衰减` 排序。

| 交付物 | 说明 |
|--------|------|
| `domain/diagnosis.py` | 级联定位算法 |
| 诊断报告 | "薄弱根源 Top-3 + 证据链" |
| 前端诊断页 | 展示诊断路径（DAG 高亮） |
| 诊断准确率评估 | 用合成数据（已知真实根源）验证 |

**验收标准**
- [ ] 合成数据上，根源定位 Top-1 准确率 ≥ 60%，Top-3 ≥ 85%
- [ ] 诊断结论必须给出**证据链**（不能只给一个结论）
- [ ] 明确写出"诊断仅供参考"，不做绝对化表述

---

### P4 · 复习调度：遗忘模型 + 间隔重复

**目标**：从"你该复习了"升级到"**今天该复习这 3 个知识点，顺序是这个**"。

| 交付物 | 说明 |
|--------|------|
| 遗忘模型 | 先用 SM-2（简单可靠），有余力再上 FSRS |
| 调度器 | 输入：掌握度 + 上次复习时间 + 目标保持率 → 输出今日复习队列 |
| 复习 API | `GET /api/students/{id}/review-queue` |
| **A/B 实验设计** | 对照组按固定顺序，实验组按模型调度，两周后测保持率 |

**验收标准**
- [ ] 调度队列可解释（每个知识点都要说明"为什么今天复习它"）
- [ ] A/B 实验方案可执行（含分组、时长、评估指标、分析脚本）
- [ ] 至少跑通一轮模拟实验（用合成数据）

### P5 · IRT 题目标定（若干轮，可延后）

**目标**：题目难度**不由我们标，由数据标**。

**2PL 模型**：$P(\text{答对}) = \frac{1}{1+e^{-a(\theta-b)}}$
- $\theta$ = 学生能力，$b$ = 题目难度，$a$ = 区分度
- **鸡生蛋问题**：θ 和 b 都不知道，要联合估计（EM 或 MCMC）

| 交付物 | 说明 |
|--------|------|
| `domain/irt.py` | 2PL + 联合估计 |
| 题目质量报告 | 区分度 a < 0.3 的题建议淘汰 |
| 自动组卷 | 给定知识点覆盖 + 目标难度分布 → 选题（这是个组合优化问题） |

**价值**：能自动筛掉"所有学生都答对"或"没人答对"的废题 —— 这对题库质量是刚需。

### P6 · 教师端★ 决定能不能进真实课堂

**目标**：让老师能用起来。**老师才是买单的人。**

| 模块 | 内容 |
|------|------|
| **角色与鉴权** | 首次引入真正的用户系统：学生 / 教师 / 管理员；JWT |
| **班级热力图** | 知识点 × 学生的掌握度矩阵，一眼看出全班卡在哪 |
| **薄弱点聚类** | 全班共同薄弱的知识点排序 + 与 DAG 结合看是否同一根源 |
| **AI 产出审核队列** | HITL 的教师版：老师审核 Agent 生成的讲解/题目，通过/修改/驳回 |
| **组卷与发布** | 按知识点覆盖 + 难度分布组卷，发布给班级 |
| **学情报告导出** | PDF/Markdown，给老师存档或发给家长会 |

**验收标准**
- [ ] 走通"教师登录 → 看班级热力图 → 发现全班在某知识点薄弱 → 组卷发布 → 学生做 → 回看热力图变化"完整链路
- [ ] 教师只能看自己的班（权限隔离**要有测试**）
- [ ] 审核队列的修正**真的回流**到生成流程（不是只存着）

### P7 · 数据飞轮闭环

**目标**：让系统**越用越好**，并且**能量化地证明**它变好了。

| 环节 | 做法 |
|------|------|
| 收集 | 教师修正 + 学生反馈 + 批改分歧 |
| 分类 | 自动归类失败模式（幻觉 / 检索失败 / 数学错 / 表述问题） |
| 回流 | 修正后的高质量样本 → 进知识库 / 改 prompt / 调检索权重 |
| 度量 | ★ **修正率随时间下降** 是飞轮转起来的核心指标 |

**验收标准**
- [ ] 有失败模式的自动分类（≥4 类）
- [ ] 有"修正率趋势"图表 —— 这是证明系统在变好的唯一证据

## 六、角色分工（沿用 R1–R5）

| 角色 | B线 Own | 说明 |
|------|---------|------|
| **R1** | 知识点 DAG 标注 + 内容组织 + 隐私合规 | 需要和老师打交道，DAG 质量决定后面所有模型的上限 |
| **R2** | P0 做题闭环的编排 + P3 级联诊断 | 图算法 + LangGraph 扩展 |
| **R3** | **P2 BKT + P5 IRT**（技术核心） | 概率模型 + EM，本阶段技术含量最高的活 |

- **评估**由 R5 牵头，但每个模型都要提供自己的离线评估脚本

## 七、风险登记

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| 1 | **拿不到真实学生数据 / 拿不到知情同意** | B线根本跑不起来 | ★ 第一周就去问老师；同时**用合成数据把全链路跑通**，不阻塞开发 |
| 2 | **数据量不足以拟合个人参数** | 模型退化成群体平均 | 分层贝叶斯：个人参数以群体为先验；数据少时自动降级 |
| 3 | 知识点 DAG 标注质量差 | 级联诊断全错 | 双人独立标注 + Kappa 一致性 + 老师抽查 |
| 4 | BKT 实现有 bug 但看不出 | 后面全建立在错误模型上 | ★ 用**合成数据**验证参数还原；用**公开数据集**对标文献 |
| 5 | 学生数据合规问题 | 项目不能上真实课堂 | 见 Q4；优先私有部署；脱敏+审计日志 |
| 6 | 教师端做完了老师不用 | 白做 | ★ **P0 阶段就去访谈 2–3 位老师**，问"你实际想看什么"，不要自己猜 |
| 7 | 范围过大，每条都停在 demo | 最大的陷阱 | 严格按里程碑走；P5/P7 可以砍 |
| 8 | 题库质量差（全是送分题/超纲题） | IRT 标定无意义 | P0 就把题目来源定好（教材习题优先，有标准答案） |

## 八、立即可做的第一周

**别急着写模型。这周做四件事：**

- [ ] **访谈 2–3 位老师**（R1 + R4）：问三个问题
  - 你现在怎么知道全班哪里没掌握？（大概率是"靠批作业的感觉"）
  - 如果有个系统能告诉你，你最想看什么？
  - 你愿意让学生用它做题吗？有什么顾虑？
  > 这三个答案会**直接改掉上面 P6 的设计**。不要跳过这一步。
- [ ] **写 `contracts/attempt.schema.json`**（R4）：把 Q1 那张表冻结成契约。
  这是整个 B线的地基，改一次代价极大。
- [ ] **写合成数据生成器**（R5）：给定真实参数 → 生成作答序列。
  这是 P2/P3 的验证基础，**先于模型写**。
- [ ] **确认隐私合规路径**（R1）：向老师/学校问清"学生数据能不能收、要不要同意书、批改能不能发云端"。

**周末验收**：四件事都有产出，且 `attempt.schema.json` 经过全组评审。
