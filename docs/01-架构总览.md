# 01 · 架构总览

> 面向：全体成员。读完你应该能回答「一个提问从浏览器出发，到答案回来，中间经过了什么」。

---

## 1. 一句话架构

```
浏览器（免构建 ESM）
   │  ① POST /api/chat/stream（SSE）
   ▼
FastAPI 服务层
   │  ② 建 Run、注入运行时依赖、启动后台任务
   ▼
LangGraph 编排内核
   │  ③ Orchestrator 路由 → 条件边并行 fan-out → Verifier → HITL 闸门 → Aggregate
   ▼
Agent 层（7 个，一人一文件）
   │  ④ 通过 RunContext 调 LLM、调工具、emit 事件
   ▼
工具层（16 个，@tool 自动注册）+ 领域层（SymPy 纯计算）
   │
   └─⑤ 事件写进 run.queue ──► SSE ──► 前端「协作轨迹」面板实时渲染
```

---

## 2. 五条设计原则（每条都对应一个具体痛点）

### 原则一：契约优先（Contract First）

前后端之间**只有一条约定**：`contracts/events.schema.json`。
后端不认识 HTML，前端不认识 LangGraph。

**收益**：两个人可以同时开工。前端同学用 Mock 事件先做界面，后端同学按契约发事件，
第一次联调就能通。

### 原则二：自动发现（Auto-discovery）

```
app/agents/*.py   →  discover_agents()   →  AgentRegistry
app/tools/*.py    →  discover_tools()    →  ToolRegistry
app/api/*.py      →  discover_routers()  →  FastAPI include_router
features/*/       →  gen_registry.py     →  features.registry.js
```

**收益**：五人并行开发**零文件冲突**。你不需要在 `__init__.py` 里登记自己的模块，
也就永远不会和别人改到同一行。

### 原则三：流式与编排解耦（Transport ≠ Orchestration）

Agent 不 `return` 给 HTTP，而是 `ctx.emit(event)` 写进 `run.queue`；
SSE 端点只是消费这个队列。

**收益**：
- Agent 内部可以随时发进度、工具调用、产物，不受 LangGraph stream_mode 限制；
- **单个 Agent 可以脱离 LangGraph 单独测试**（见 `scripts/smoke_test.py`）；
- 换传输（WebSocket / 轮询）不影响任何 Agent 代码。

### 原则四：能算的不要问模型（Determinism over Generation）

| 问题 | 交给谁 | 为什么 |
|------|--------|--------|
| 这是什么意图？ | 规则路由（`agents/_router.py`） | 免费、毫秒级、100% 可复现；规则失配才用 LLM 兜底 |
| 期望/方差/矩母函数是多少？ | SymPy（`domain/distributions.py`） | LLM 会算错，符号计算不会 |
| 从提问里抽分布和参数 | 正则（`extract_distribution`） | 抽错会直接导致算错，不能赌 |
| 组织语言、讲清概念 | LLM | 这是它真正的强项 |
| 结论对不对？ | Verifier（独立复检）+ HITL | 分权，且最终由人拍板 |

### 原则五：离线可用（Offline-capable）

KaTeX 本地 vendor、动画自包含、Mock Provider、SQLite。
断网、没 Key、内网答辩都能完整演示。

## 3. 后端分层

```
backend/app/
├── config.py          【配置】所有可调项集中一处
├── domain/            【领域】纯逻辑，无 IO / 无 LLM / 无框架，可单独单测
│   └── distributions.py   8 种分布的符号推导 + 数值采样
├── kernel/            【内核】编排机制，与业务无关
│   ├── events.py          事件协议（与 contracts/events.schema.json 一一对应）
│   ├── specs.py           AgentSpec / ToolSpec / RunContext / @tool
│   ├── registry.py        自动发现
│   ├── state.py           LangGraph AgentState
│   ├── graph.py           图装配（唯一的编排拓扑定义）
│   └── runs.py / runner.py  运行注册表 + 流式运行器
├── agents/            【业务·生成】一人一文件
├── tools/             【业务·能力】一人一文件
├── providers/         【基础设施】LLM 抽象（deepseek / mock）
└── api/               【接口】一人一文件，自动挂载
```

**依赖方向是单向的**：
`api → kernel → (agents, tools) → domain`。
`domain` 不 import 任何上层；`kernel` 不 import 具体 Agent（靠注册表注入）。
这条纪律保证了任何一层都能被替换。

## 4. 怎么新增一个 Agent（最重要的扩展点）

> **场景**：你要做一个「错题本 Agent」。

**第 1 步**：新建 `backend/app/agents/mistake_book.py`

```python
from ..kernel.specs import AgentResult, AgentSpec, RunContext

SPEC = AgentSpec(
    id="mistake_book",
    name="Mistake Book Agent 错题本",
    role="generator",                    # router | generator | verifier | analyst | tool
    description="整理并归类用户的错题，输出复习清单。",
    intents=("analytics", "solve"),      # 哪些意图会路由到它
    tools=("kb_search", "learning_stats"),  # 角色门控：只能调这些
    emits=("table",),
    accent="#0EA5E9",
    icon="📕",
)

async def run(state: dict, ctx: RunContext) -> AgentResult:
    stats = await ctx.use("learning_stats", session_id=state["session_id"])
    text = await ctx.stream_llm(
        "你是错题整理助手…（系统提示）",
        f"【用户问题】{state['query']}",
    )
    ctx.emit_artifact("table", {
        "title": "错题清单",
        "columns": ["知识点", "次数"],
        "rows": [[w["topic"], w["attempts"]] for w in stats.get("weak_topics", [])],
    })
    return AgentResult(agent=SPEC.id, text=text, data={"n": len(stats.get("weak_topics", []))})
```

**第 2 步**：把 `mistake_book` 加进 `_router.py` 的 `INTENT_AGENTS`（**这是唯一需要改的共享文件，
而且只是往一个 dict 里加一个 key**）。

**第 3 步**：重启服务。完成。

你**没有**改：`graph.py`、`agents/__init__.py`、`registry.py`、任何前端文件。
图会自动把它挂进并行 fan-out，`/api/agents` 会自动返回它，前端工作台会自动显示它的角色卡。

> 如果你希望连 `_router.py` 都不用改，可以在 `SPEC.intents` 里声明意图，
> 由 `AgentRegistry.by_intent()` 兜底发现（kernel 已提供这个方法）。

## 5. 怎么新增一个前端页面

**第 1 步**：新建目录 `frontend/app/features/mistakes/`

`feature.json`：

```json
{
  "id": "mistakes",
  "dir": "mistakes",
  "title": "错题本",
  "icon": "📕",
  "route": "mistakes",
  "group": "学习",
  "order": 35,
  "subtitle": "错题整理与复习清单"
}
```

`index.js`：

```js
import { h, injectStyles } from '../../core/dom.js';
import { createRunPanel } from '../../components/run-panel.js';

injectStyles('/app/features/mistakes/styles.css');

let panel = null;

export function mount(container, ctx) {
  container.append(h('div', { class: 'card' },
    h('div', { class: 'card-title' }, '📕 错题本')));

  const host = h('div', { class: 'mt-16' });
  container.append(host);
  panel = createRunPanel(host, {
    placeholder: '看看我最近错在哪',
    examples: ['整理我的薄弱知识点'],
  });
}

export function unmount() {
  panel?.destroy();   // 必须：回答区可能挂着动画 iframe
  panel = null;
}
```

**第 2 步**：`python scripts/gen_registry.py`

**第 3 步**：刷新浏览器。导航里出现了。

你**没有**改 `index.html`、`bootstrap.js`、导航数组。

> **强烈建议复用 `createRunPanel`**：它已经处理好了流式渲染、Markdown + KaTeX、
> 多 Agent 轨迹、产物挂载、HITL 交互、取消、节流。自己重写一遍不划算。

## 6. 前端模块图

> **技术栈口径以 [`docs/23-前端技术栈口径.md`](23-前端技术栈口径.md) 为准。**
> 本节只画主站 SPA（ESM 那一半）的模块图；"悬浮窗为什么必须是经典脚本""两边怎么共享同一份逻辑"
> "生成式产物的规则"都在 `docs/23`。

```
index.html                 ← 只有布局骨架 + 挂载点（#nav / #view-host）
└── app/bootstrap.js       ← 唯一的装配点
    ├── shared/            ← ★ 跨形态共享的纯逻辑（主站与悬浮窗共用同一份实现）
    │   ├── sse.js         SSE 帧解析（协议层，widget 侧也用它）
    │   ├── markdown.js    Markdown 子集 → HTML
    │   ├── math.js        公式定界符归一化 + KaTeX 渲染入口
    │   ├── api.js         HTTP 客户端内核
    │   └── events.js      ★ 生成文件：14 种事件类型常量（源：contracts/events.schema.json）
    ├── core/              ← 主站装配层（可直接 import shared/）
    │   ├── bus.js         事件总线（feature 之间唯一的通信方式，禁止互相 import）
    │   ├── store.js       极简响应式状态
    │   ├── router.js      路由 + feature 注册 + 导航渲染 + 角色守卫
    │   ├── dom.js         h() / esc / toast / injectStyles / debounce
    │   ├── auth.js        令牌 / 会话 / 访问规则
    │   └── api.js         唯一允许 fetch 的地方（薄封装 shared，含 SSE 客户端）
    ├── components/        ← 跨 feature 复用
    │   ├── run-panel.js       ★ 提问→协作→产出的完整交互骨架
    │   ├── trace.js           ★ 多 Agent 协作轨迹面板
    │   ├── artifacts.js       产物渲染（animation/chart/formula/steps/table）
    │   ├── animation-player.js ★ 同源 iframe 驱动 8 个动画
    │   ├── markdown.js        转出 shared/markdown.js（对外导出名不变）
    │   ├── katex.js           转出 shared/math.js
    │   └── chart.js           零依赖 Canvas 折线/柱状图
    └── features/          ← 一人一目录
```

**另一条投递路径（悬浮窗）**：它**不改模块格式**（经典脚本 IIFE + `__PSA`），
通过生成产物 `widget/_shared.js` 消费上面那个 `shared/`。理由与规则见 `docs/23` §1.1。

**样式分层**：`tokens.css`（变量）→ `app.css`（外壳与原子）→ `components.css`（共享组件）
→ `pages.css`（页面模板）→ `<feature>/styles.css`（页面私有）。
一个 feature 的样式**只允许**写在它自己的 `styles.css` 里；若两个页面都要用，
就提升到 `components.css`（本项目里 `.wb-hero`、`.dist-chip` 就是这么处理的）。
**设计 token 只允许定义在 `tokens.css`** —— 别处写死的色值都是缺陷（现存债务见 `docs/23` §五）。

## 7. 关键机制速查

| 机制 | 位置 | 说明 |
|------|------|------|
| 并行 fan-out | `kernel/graph.py` `route_after_orchestrator` | 条件边返回列表 = 并行；`state.results` 用 `operator.add` reducer 自动合并 |
| HITL 挂起 | `kernel/graph.py` `hitl_gate_node` | LangGraph 原生 `interrupt()`，checkpointer 保存现场 |
| HITL 恢复 | `kernel/runner.py` `resume_run` | `Command(resume=...)`，**不重跑已完成节点** |
| 事件通道 | `kernel/runs.py` `Run.queue` | Agent emit → 队列 → SSE 消费 |
| 角色门控 | `kernel/specs.py` `ToolRegistry.call` | Agent 只能调 `SPEC.tools` 里声明的工具 |
| 生成/验证分权 | `agents/verifier.py` | 独立复检步骤完整性、教材依据、公式定界符 |
| 动画桥接 | `tools/animation.py` + `components/animation-player.js` | 关键词推荐 + 同源 iframe 驱动 |
| 会话身份 | `bootstrap.js` `ensureSessionId()` | 浏览器本地 id，替代登录系统 |
