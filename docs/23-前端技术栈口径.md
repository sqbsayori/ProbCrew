## 一、适用范围：三种形态，两套加载方式

前端有**三种交付形态**，它们的技术栈**故意不同**，这不是历史遗留，是约束决定的：

| 形态 | 目录 | 模块格式 | 入口 | 为什么这样 |
|---|---|---|---|---|
| **主站 SPA** | `frontend/app/` | **原生 ESM**（`import`/`export`） | `index.html` 里 `<script type="module" src="/app/bootstrap.js">` | 免构建、动态 import 加载 feature（ADR-0001） |
| **悬浮窗** | `frontend/widget/` | **经典脚本**（IIFE + `window.__PSA`） | ① `loader.js` 顺序注入 ② 油猴脚本 `@require` | **必须如此**，见下 |
| **演示课件页** | `frontend/course/` | 纯静态 HTML/CSS | 直接托管 | 模拟真实课程平台，故意"什么框架都没有" |

### 1.1 悬浮窗为什么必须是经典脚本（**不许"顺手统一成 ESM"**）

1. **油猴 `@require` 只接受经典脚本**。Tampermonkey 在**安装时**把这些文件抓下来缓存，
   **运行时不再受目标站点 CSP 限制** —— 这正是它能在智慧树这类平台上工作的原因
   （见 `frontend/widget/probstat-assistant.user.js:57-62` 的注释）。
2. 改成 ESM 就只剩"向宿主页面注入 `<script type="module">`"这一条路，
   而宿主页面的 `script-src` CSP 会直接拦掉它 —— 我们最大的未知数（`docs/17` 任务 D2：
   真实平台读屏）会因此从"待验证"变成"注定失败"。
3. 结论：**两种加载方式长期并存**。统一的对象不是"模块格式"，而是**它们消费的逻辑**。

## 二、目录与职责（统一后的目标结构）

```
frontend/
├── shared/                  ★ 唯一真相来源：跨形态复用的纯逻辑（ESM）
│   ├── sse.js                   SSE 帧解析（协议层）
│   ├── markdown.js              Markdown 子集 → HTML（含公式占位）
│   ├── math.js                  公式定界符归一化 + KaTeX 渲染入口
│   ├── api.js                   HTTP 客户端内核（URL 拼装 / 认证头注入点 / 错误语义）
│   └── events.js                ★ 生成文件：14 种事件类型常量（源：contracts/events.schema.json）
│
├── app/                     主站 SPA（ESM，可直接 import shared/）
│   ├── core/                    装配层：router · store · bus · dom · auth · api（薄封装 shared）
│   ├── components/              视图组件：markdown · katex · chart · trace · run-panel …
│   └── features/<页>/           一人一目录：feature.json + index.js + styles.css
│
├── widget/                  悬浮窗（经典脚本）
│   ├── _shared.js               ★ 生成产物：shared/ 的经典脚本包（勿手工编辑）
│   ├── _modules.json            ★ 生成产物：模块加载清单（UI 全量 / FRAME 子集）
│   ├── api.js · render.js       薄适配层：从 __PSA.shared 取实现，自身不再有逻辑
│   ├── assistant.js · pet.js · extractor.js · frames.js · anim-bridge.js
│   ├── widget.css               Shadow DOM 内自足的样式
│   └── probstat-assistant.user.js   油猴脚本（@require 顺序由 CI 校验）
│
├── styles/                  全局样式层（只此一处）
│   ├── tokens.css               设计令牌（颜色/圆角/阴影的唯一来源）
│   ├── app.css                  外壳骨架 + 原子组件
│   ├── components.css           跨页共享的领域组件
│   └── pages.css                页面模板层（页头/工具栏/表格/空状态/登录页…）
│
├── course/ · assets/ · vendor/   课件演示页 · 动画资产（只读）· 本地 KaTeX
└── _test/harness.mjs        ★ 计划中：三个测试共用的 DOM 桩（阶段 2）
```

## 三、依赖方向（**硬规则，CI 会查**）

```
        ┌──────────────┐
        │   shared/    │  纯逻辑，无环境依赖
        └──────┬───────┘
       import  │  import              ┌─────────────────────────┐
     ┌─────────┴─────────┐            │ widget/ 源码**不 import** │
     ▼                   ▼            │ 它消费生成产物 _shared.js │
┌─────────┐        ┌──────────┐       └─────────────────────────┘
│  app/   │        │ widget/  │◀──────  __PSA.shared（生成时注入）
└─────────┘        └──────────┘
```

| 规则 | 说明 |
|---|---|
| **R1** | `shared/` **禁止** import `app/` 或 `widget/` 的任何文件 |
| **R2** | `shared/` **禁止**出现 `document`、`window`、`localStorage`、`fetch`、`location` —— 需要这些能力时由调用方**注入**（生成器会静态检查并在命中时报错） |
| **R3** | `app/` 可以 import `shared/`；`app/features/*` **禁止**互相 import（沿用 ADR-0001：只走 `core/bus.js`） |
| **R4** | `widget/` 的源码**不做 import**（它是经典脚本）；它只能通过 `__PSA.shared` 消费共享逻辑 |
| **R5** | `shared/` 内部只允许**相对导入**、只允许**具名导出**、**禁止循环依赖**、**禁止顶层 await** |
| **R6** | 跨页共享的样式只能放 `styles/`；页面专属样式只能放 `features/<页>/styles.css` |

## 四、生成式产物（零构建的**唯一**例外）

为什么不破例不行：共享内核是 ESM，而悬浮窗要经典脚本；手工维护两份就是现在这副样子。

| 项 | 规定 |
|---|---|
| 生成器 | `scripts/build_widget.py`（**纯 Python 标准库**，不引入 npm / 打包器） |
| 产物 | `frontend/widget/_shared.js`（经典脚本包）+ `frontend/widget/_modules.json`（加载清单） |
| 产物归属 | **提交进仓库**（与 `contracts/api.md`、`features.registry.js` 同一套做法：生成 + 提交 + CI 校验新鲜度） |
| 产物文件头 | 必须写明「本文件由 `scripts/build_widget.py` 自动生成，请勿手工编辑」+ 生成器路径 |
| CI 校验 | `python scripts/build_widget.py --check` —— 重新生成后与磁盘比对，不一致即红灯 |
| 失败行为 | 生成器遇到不支持的语法（非相对导入 / default export / 循环依赖 / 顶层 await / 触碰 DOM）**立即报错退出并指明文件:行**，**绝不产出半成品** |
| 油猴 `@require` | 由 CI 校验"顺序与内容 == `_modules.json`"，但**生成器不自动改写手写文件** |
| 何时取消 | 阶段 3 若把 7 个 widget 模块并成单文件产物，`@require` 可从 8 行降到 1 行 —— 属于优化，不是必须 |

> **与 `ADR-0001` 的关系**：ADR-0001 的核心承诺（无 npm、无 `node_modules`、无打包器、离线可用、静态托管）
> **全部仍然成立**。本文只是为零构建开了一个最小例外：**纯 Python 的确定性拼接**，产物进仓库可审。
> 该决定的记录见 `docs/adr/0003-前端共享内核与生成式产物.md`。

## 五、样式口径

| 规则 | 说明 |
|---|---|
| token 唯一来源 | `frontend/styles/tokens.css`。**任何写死的色值都是缺陷**（改主题会漏） |
| 层次 | `tokens.css`（变量）→ `app.css`（外壳与原子）→ `components.css`（跨页领域组件）→ `pages.css`（页面模板）→ `features/<页>/styles.css`（页面专属） |
| 悬浮窗 | 样式在 **Shadow DOM 内自足**（宿主样式进不来，我们的也出不去）；**样式一律不注入宿主 `<head>`**。唯一允许写宿主的地方是 KaTeX 的 `<script>`（Shadow DOM 承载不了脚本作用域）——油猴路径将来改成 `@require` 可把它也去掉，登记在阶段 2 |
| 现状债务 | `widget/widget.css` 有 **77 处硬编码色值（23 种，其中 13 种与 tokens 同值）** → 阶段 2 改为从 tokens 生成变量块 |
| 命名 | 共享层类名不加前缀（`.card`/`.btn`/`.stat-grid`）；页面专属类名带页面前缀或放本页 `styles.css`；**不许在页面里覆盖共享层的同名类** |

## 六、事件口径

| 规则 | 说明 |
|---|---|
| 唯一来源 | `contracts/events.schema.json`（14 种事件类型） |
| 前端常量 | 由 `scripts/gen_events_js.py` 生成 `shared/events.js`（**生成产物，勿手工编辑**） |
| 禁止 | 前端不许手写事件类型字符串字面量；两处分发（`app/components/trace.js`、`widget/assistant.js`）都必须消费常量 |
| 为什么 | 现状：`trace.js` 覆盖 13 种、`assistant.js` 覆盖 11 种、契约里 14 种 —— 三者不一致，新增事件只能靠记忆 |
| 兜底 | 新增事件类型时，CI 的契约校验会红；分发处漏覆盖由 `shared/_test_shared.mjs` 的"未处理类型"断言兜住 |

## 七、测试口径

| 入口 | 作用 | 必须保持 |
|---|---|---|
| `frontend/app/_test_mount.mjs` | 每个 feature 的 mount/unmount + 关键区块 + 路由守卫回归 | 10 页 10/10 |
| `frontend/widget/_test_render.mjs` | 渲染器归一化（6 项） | 6/6 |
| `frontend/widget/_test_deploy.mjs` | 部署无关化（19 项） | 19/19 |
| `frontend/shared/_test_shared.mjs` | ★ 新增：共享内核单测 + **两边等价性** | 全绿 |

规则：
1. **凡改 `shared/` 必须带对应测试**（否则等价性无从保证）；
2. **等价性测试是本口径的哨兵**：同一批输入分别喂给主站侧与悬浮窗侧，**输出必须逐字相同** —— 红灯就说明"统一"没做到；
3. 阶段 2 把三套 DOM 桩合并成 `frontend/_test/harness.mjs`（现状：`app/_test_mount.mjs` 自带 432 行桩，widget 两个测试各一套）。

## 八、红线（禁止事项）

1. **禁止**在 `widget/` 里再写第二份 Markdown / SSE / API 解析 —— 唯一实现只能在 `shared/`。
2. **禁止**引入 npm 依赖、打包器（Vite/Webpack/Rollup/esbuild）。生成式产物是唯一例外，且必须是纯 Python。
3. **禁止**在 `shared/` 里直接触碰 `document`/`window`/`localStorage`/`fetch`（要注入）。
4. **禁止**手工编辑任何带"自动生成"抬头的文件（`_shared.js`、`_modules.json`、`shared/events.js`、`contracts/api.md`、`features.registry.js`）。
5. **禁止**绕开 `core/bus.js` 做 feature 之间的互相 import。
6. **禁止**把地址、后端 URL、密钥写死在前端（沿用 `docs/13 §2.3` 的部署无关化约定，CI 已查）。
7. **禁止**为了"统一"把悬浮窗改成 ESM（见 §1.1，那会破坏绕 CSP 的能力）。

### 9.1 按 X3 收缩时**不要**做的事

`docs/20` 已定：悬浮窗最终收缩为「**只读探针 + 提问 + 主站入口**」（任务 `X3`，当前暂缓）。因此：

- **不要**为 `widget/pet.js`（Canvas 形象）、`widget/anim-bridge.js` 的 `control()`（驱动宿主动画）建任何共享抽象 —— 它们的命运是被删除；
- 共享层只覆盖**会被两种形态长期共用**的东西：SSE 协议、Markdown/公式渲染、HTTP 客户端语义、事件常量；
- `X3` 解冻时，`anim-bridge.js` 只保留只读部分（`isAnimationPage()` / `state()` / `stateText()`），
  驱动部分随 `assistant.js` 的控制条一起删。
