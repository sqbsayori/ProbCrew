# 03 · 动画接入规范

> 面向：负责把交互动画接入系统的同学（R1）以及任何要新增动画的人。
> **前置阅读**：`docs/notes/动画接入勘测.md`（对 8 个动画逐个的实测结论）。

---

## 1. 核心决定：动画文件**不改**

8 个动画是自包含的（vanilla JS + Canvas，**零 CDN 依赖**），这本身是宝贵的资产：
能离线、能单独分发、能塞进任何数字教材。系统不去"改造"它们，而是**发现 + 呈现 + 远程驱动**。

因此接入一个新动画 = **放文件 + 写一条清单**，不碰任何 JS。

---

## 2. 目录约定

```
frontend/assets/animations/
├── manifest.json          ← 唯一需要手写的清单（数据驱动）
├── adapter.html           ← 独立播放器（不带 SPA 外壳，统一控制条）
└── _raw/                  ← 原始动画文件，只读，禁止修改
    ├── 贝叶斯公式(g).html
    ├── 布丰投针(g).html
    ├── 马尔科夫链 (g).html      ← 注意文件名里有空格
    ├── 随机变量变换可视化交互动画(g).html
    ├── 中心极限定理(g).html
    ├── 连续型边缘分布生成演示动画(g).html
    ├── 网络流量仿真(g).html
    └── 推荐系统马尔可夫链(g).html
```

服务端把该目录挂在 `/animations`，所以 URL 是
`/animations/_raw/<文件名>`、`/animations/manifest.json`、`/animations/adapter.html?id=bayes`。

## 3. manifest.json 字段规范

```jsonc
{
  "version": 1,
  "basePath": "/animations/_raw/",
  "adapter": "/animations/adapter.html",
  "categories": ["全部", "概率基础", "随机过程", "仿真建模", "应用案例"],
  "animations": [
    {
      "id": "bayes",                       // 必填，唯一，ASCII kebab-case
      "title": "贝叶斯公式",                 // 必填，中文标题
      "file": "贝叶斯公式(g).html",          // 必填，_raw/ 下的真实文件名（含 (g)，含空格）
      "category": "概率基础",                // 必填，取自 categories
      "description": "通过先验、似然和后验的动态变化，理解贝叶斯更新思想。",
      "icon": "🧠",
      "accent": "#2f6df6",

      "concepts": ["贝叶斯公式","先验概率","似然","后验概率","条件概率","全概率公式"],
      // ↑ 关键词推荐的核心。中文 bigram 匹配，写得越贴近学生提问越好。

      "chapter": "ch01",                   // ch01..ch09
      "agentIntents": ["knowledge","visualize"],
      "canvasCount": 0,                    // 实测值；0 表示纯 DOM/CSS 实现

      "controls": {                        // ★ 必须是真实存在的 #id 选择器
        "play":  "#playBtn",
        "pause": "#pauseBtn",
        "reset": "#resetBtn",
        "step":  "#stepBtn"
      },

      "params": [                          // 用户可调输入（信息展示用）
        { "name": "prior", "label": "先验概率", "selector": "#pPrior",
          "type": "range", "min": 0, "max": 1, "step": 0.01, "default": 0.5 }
      ],
      "readouts": ["后验概率","先验","似然"],
      "embedNotes": "顶部横幅较宽，建议 iframe 宽度 ≥ 1000px"
    }
  ]
}
```

### `controls` 的硬性要求

`controls` 是**唯一**决定"能不能远程驱动"的字段，必须如实填写实测到的 `#id`。
填错的后果是按钮点不动 —— 而 `scripts/smoke_test.py` 第 5 节会自动抓出这种错误：

```
✔ 所有 controls 选择器在真实 HTML 中存在  — 8/8 可驱动
```

所以要验证自己写的清单，跑一次自检即可。

**已实测结论（8 个动画扫过一遍）**：

| 动画 | play | pause | reset | step |
|------|------|-------|-------|------|
| 除 markov-chain 外 7 个 | `#playBtn` | `#pauseBtn` | `#resetBtn` | `#stepBtn` |
| **markov-chain** | **`#startBtn`** ⚠️ | `#pauseBtn` | `#resetBtn` | `#stepBtn` |

绑定方式有两派（5 个用 `addEventListener`，3 个用 `onclick`），
但对 `iframe.contentDocument.querySelector(sel).click()` **无差别**，不用管。

## 4. 新增一个动画的完整步骤

1. 把 HTML 放进 `frontend/assets/animations/_raw/`（**不要改名、不要格式化、不要改代码**）。
2. 打开它，用 F12 确认四个控制按钮的真实 `id`；顺便记录可调 input 的 id 与取值范围。
3. 在 `manifest.json` 的 `animations` 数组里加一条，`concepts` 写 5–8 个学生可能用到的问法关键词。
4. 跑 `python scripts/smoke_test.py`，确认第 5 节全绿。
5. 刷新浏览器 → 动画库、Agent 推荐、`/api/animations` 全部自动生效。
6. 在 `docs/notes/动画接入勘测.md` 追加一行勘测记录。

**不需要**改：任何 `.js`、任何后端文件、任何配置。

## 5. 播放器实现要点（`components/animation-player.js`）

这些是实测踩出来的坑，改播放器时务必保留：

### 5.1 必须同源 http，不能 `file://`

`file://` 下 iframe 是 opaque origin，`contentDocument` 会被浏览器拒绝，控制全部失效。
这就是系统把动画挂在 FastAPI 静态目录、而不是让用户双击 html 的原因。
`adapter.html` 里也写了醒目提示。

### 5.2 必须先给非零尺寸，再设 `src`

零宽/隐藏的 iframe 首帧会画成 **0×0 空白**（部分动画在 `load` 时读 `clientWidth`）。
播放器的做法：

```js
const stage = h('div', { style: { minHeight: `${height}px` } });
// 等 stage 量到真实宽度后才 createElement('iframe') 并 append
requestAnimationFrame(mountIframe);
```

### 5.3 `load` 之后要补派发 `resize`

部分动画只在 `window.resize` 时才按 `devicePixelRatio` 重算 canvas 位图，
否则在高分屏下会发虚。所以：

```js
iframe.addEventListener('load', () => {
  iframe.contentWindow.dispatchEvent(new Event('resize'));
});
```

另外用 `ResizeObserver` 监听容器，尺寸变化时继续补派发。

### 5.4 ★ 离开页面必须**销毁 iframe**，不能只 `display:none`

`马尔科夫链 (g).html` 的 `draw()` 末尾无条件 `requestAnimationFrame(draw)` 自递归，
而 `pause()` 只清 `setInterval`、停不掉重绘循环；这些函数都在 IIFE 闭包内，外部无法干预。
**后果**：SPA 里切走的 iframe 会一直烧 CPU（风扇会响）。

正确做法：

```js
destroy() {
  iframe.src = 'about:blank';
  iframe.remove();      // 彻底移除节点
  iframe = null;
}
```

因此每个挂载了动画的 feature，`unmount()` 里都**必须**调用 `panel.destroy()` 或
`player.destroy()`；`artifacts.js` 提供了 `destroyArtifacts(root)` 递归清理。

### 5.5 宽布局与全屏

动画页面本身是 PC 双栏布局，断点在 1000–1180px；**iframe 宽度 < 1120px 会掉成单列**（不难看但变长）。
因此播放器提供「⛶ 全屏」（近全宽浮层），窄容器下推荐用户用它。

## 6. 后续可选优化：给动画加标准接口（v2）

目前的驱动方式是"点按钮"，能力上限就是原作按钮的能力（无法设参数、无法读取当前状态）。
如果后续想要更强的联动（例如让 Agent 直接把 `λ=3` 灌进动画），推荐加一个**统一导出**：

在动画 HTML 的脚本末尾加 3 行（**需要修改原作，属于 v2 才做的事**）：

```js
// 在动画自身的 IIFE 内部追加
window.__ANIM__ = {
  play, pause, reset, step,             // 复用已有函数
  setParams: (p) => { /* 写 input.value 并触发一次重算 */ },
  getState: () => ({ step: stepCount, current }),
};
```

播放器侧改成优先探测 `window.__ANIM__`，探测不到再回退到"点按钮"：

```js
const api = iframe.contentWindow.__ANIM__;
if (api?.setParams) api.setParams({ lambda: 3 });
else click('#applyBtn');   // 回退
```

**现状**：8 个动画的函数全部封在 IIFE 闭包里，唯一例外是
`随机变量变换可视化交互动画(g).html`（顶层作用域，可直接 `contentWindow.step()`）。
参数目前只能靠"改 input.value + 派发 input 事件"来设置，`params[].selector` 字段就是为此预留的。

> 建议：**先不动原作**。等真的有"参数注入"的强需求时，按上面方案一次改 8 个文件，
> 并把 `manifest.json` 的 `version` 升到 2、加一个 `api: "v2"` 字段做能力协商。

## 7. 验收清单

新增/修改动画接入后，逐条打勾：

- [ ] `_raw/` 下的文件未被修改（对比修改时间戳）
- [ ] `manifest.json` 是合法 JSON（`python -c "import json;json.load(open(...))"`）
- [ ] `controls` 的每个选择器都能在对应 HTML 里 grep 到
- [ ] `python scripts/smoke_test.py` 第 5 节全绿
- [ ] 浏览器里动画库能看到新卡片，能播放/暂停/单步/重置
- [ ] 切走页面后 CPU 占用回落（任务管理器确认）
- [ ] `/api/animations/recommend` 用相关关键词能推荐到它
