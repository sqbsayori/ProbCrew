## 2. 控制协议可行性结论

**结论：8 / 8 全部具备稳定 `#id` 的「play + pause + reset + step」四件套，可被同源包装页 100% 驱动。**

- **直接可按 `#id` 寻址的控制（8/8）**：每个文件的主控制区都是四个原生 `<button>`，且都有唯一 `id`。唯一命名例外是 `markov-chain`：播放按钮是 `#startBtn`（标签「开始动画」），其余三个仍为 `#pauseBtn` / `#stepBtn` / `#resetBtn`；`manifest.json` 的 `controls.play` 已按实际 id 记录。
- **没有任何一个动画使用「无 id 的中文文字按钮」**。所有按钮均由 `id` 唯一定位，不存在靠 `textContent` 或 `.btn-green` 之类的类名猜按钮的需要。旧导航页 `index.html` 的卡片按钮才是无 id 元素，但它不属于动画条目。
- **绑定方式两派**，均可在 iframe 内触发：
  - `addEventListener("click", …)`：`bayes`、`buffon-needle`、`clt`、`marginal-continuous`（`马尔科夫链` 也是 `addEventListener`，写在一行）
  - `element.onclick = …` 属性赋值：`rv-transform`、`network-traffic`、`recsys-markov`
  - 对包装页而言二者无差别，`el.click()` 都会派发真实 click 事件，两条路径都会执行。已核对的对应行：`贝叶斯公式` 1106-1112、`布丰投针` 826-836、`随机变量变换` 121、`网络流量仿真` 489-499、`中心极限定理` 1262-1271、`连续型边缘分布` 795-798、`马尔科夫链` 73、`推荐系统马尔可夫链` 610-614。
- **没有任何动画在加载时自动播放**。8 个文件的初始化调用分别是 `render()`（贝叶斯）/ `updateStats(); draw()`（布丰）/ `reset()`（随机变量变换）/ `render(1)`（CLT）/ `rebuild()` 类初始化（边缘分布）/ `init(5); draw();`（马尔科夫链）/ `reset()`（网络流量）/ `loadPreset()`（推荐系统），全部只渲染初始静态帧，没有一个是 `play()`/`start()`/`setInterval` 起手的。这对 SPA 内嵌非常友好。
- **唯一的准「自动运行」项**：`马尔科夫链` 的 `draw()` 末尾 `requestAnimationFrame(draw)` 是无条件自递归，加载后**常驻渲染循环**（即使没有转移也在每帧重绘）。`推荐系统马尔可夫链` 的 `requestAnimationFrame` 只在小球移动的 550ms 动画期间使用，不是常驻循环。
- **8 个文件均为完全自包含**：无 CDN、无 `<script src>`、无外部字体/图片依赖，因此 `file://` 直接打开也能跑。

### 包装页驱动方式（adapter.html）

```js
var doc = iframe.contentDocument;              // 必须同源，否则抛 SecurityError
doc.querySelector('#playBtn').click();         // 或 #startBtn（markov-chain）
doc.querySelector('#pauseBtn').click();
doc.querySelector('#stepBtn').click();
doc.querySelector('#resetBtn').click();
```

- **同源前提是硬约束**：动画是 `file://` 本地文件时，Chromium 把每个 `file://` 文档视为 opaque origin，**同目录 iframe 也拿不到 `contentDocument`（被当作跨域拒绝）**。因此 `adapter.html` 方案必须在 http(s) 静态服务下部署（例如 `/animations/_raw/*.html` 与 `/animations/adapter.html` 同源）。
- **异常兜底**：包装页应始终 `try/catch` 并在 `contentDocument` 为 `null` 或 `querySelector` 为空时退化为「只展示、不控制」，而不是让整个 iframe 面板报错。
- **无需补丁的项：8/8。** 没有出现「只有中文文字按钮、无 id」的动画，因此不存在「必须改动 HTML 文件」的最小补丁需求（本次勘测也按要求未改动任何动画文件）。若后续要削弱耦合，建议的最小改动方向是可选增强而非修复：
  1. 给 `markov-chain` 增加一个 `#playBtn` 别名（或同时绑定 `#startBtn` 与 `#playBtn`），统一 8 个文件的 `controls.play` 选择器；
  2. 为 `markov-chain` 的常驻 `requestAnimationFrame` 增加暂停开关（例如 `pause()` 时停止递归、`play()`/`draw()` 时恢复），以便 SPA 在隐藏面板时释放 CPU；
  3. 为 `clt`、`markov-chain`、`recsys-markov` 的 canvas 增加「按容器尺寸重设 `canvas.width/height`」的重绘分支，解决高分屏模糊（见第 4 节）。

## 3. 参数注入可行性结论

**结论：31 个可调项全部可程序化注入，但它们全部是「事件驱动」，没有任何一个提供可从外部直接调用的 `render()` API。**

注入范式（把设置值与触发合并在一次事件派发里）：

```js
var el = doc.querySelector('#lambdaRange');
el.value = 2.5;
el.dispatchEvent(new win.Event('input', { bubbles: true }));   // 必须用 iframe 自己的 Event 构造器
```

已逐个核对的参数绑定（数量即总览表的「可调参数个数」）：`bayes` 3（`#prior`/`#hit`/`#falseRate`，`input`）、`buffon-needle` 4（`#dRange`/`#lRange`/`#speedRange`/`#batchRange`，`input`）、`rv-transform` 4（`#distSelect`/`#transformSelect` 走 `change`，`#speedRange`/`#batchRange` 走 `input`）、`clt` 2（`#nRange` 走 `input`、`#distSelect` 走 `change`）、`marginal-continuous` 3（`#presetSelect`/`#modeSelect` 走 `change`、`#speedRange` 走 `input`）、`markov-chain` 3（`#nRange`/`#speedRange` 走 `input`，矩阵 `.pCell` 走 `change`）、`network-traffic` 6（`#trafficSelect` 走 `change`，`#lambdaRange`/`#capRange`/`#bufRange`/`#speedRange`/`#batchRange` 走 `input`）、`recsys-markov` 6（`#presetSelect`/`#startSelect`/`#modeSelect` 走 `change`，`#speedRange`/`#batchRange` 走 `input`，矩阵 `#matrixTable input` 走按钮触发）。

**四个必须知道的前提：**

1. **所有逻辑都在 IIFE 闭包内**（`(function(){ … })()`）。`render` / `step` / `play` / `applyMatrix` 等函数**不会挂到 `window`**，iframe 外部无法直接调用。唯一可靠的驱动通道就是 DOM 事件。唯一的例外是 `随机变量变换可视化交互动画(g).html`：它的函数写在顶层作用域（无 IIFE，仅用 `const $=…`），所以 `iframe.contentWindow.step()` / `play()` / `batch(n)` 理论上可直接调用——但建议仍然统一走事件，避免依赖该文件未被压缩/重构。
2. **矩阵类参数必须用 `change` 且部分还要按按钮**。`markov-chain` 的 `.pCell` 只监听 `change`（不是 `input`），注入后需再点 `#normalizeBtn`（归一化）或让它在下一次 `step()` 内部自行 `readMatrixFromInputs()+normalizeMatrix()`；`recsys-markov` 的 `#matrixTable input` 干脆**没有任何监听器**，必须点 `#applyMatrixBtn` 才会被 `applyMatrix()` 读走（`#normalizeBtn` 内含 `applyMatrix()`，点它等价于「应用+归一化」）。
3. **部分动画「改参数 = 重置」**，这对教学演示是特性、对自动编排是副作用：`buffon-needle`（`#dRange`/`#lRange` 的 `input` 直接调 `reset()`）、`network-traffic`（`#lambdaRange`/`#capRange`/`#bufRange`/`#trafficSelect` 全部 `reset()`）、`recsys-markov`（`#presetSelect` 走 `loadPreset()`、`#startSelect` 走 `reset()`）。也就是说「先设参数再跑」的顺序天然成立，但不能在运行中无损失地热调参——会清空已累积的抛针数 / 队列历史 / 路径。Adapter 应先 `pause()`、再注入参数、最后 `play()`。
4. **批量类参数是「值 + 按钮」两段式**：`#batchRange` 只改变显示与待用数值，真正执行要靠 `#batchBtn`（`buffon-needle`、`rv-transform`、`network-traffic`、`recsys-markov` 四个文件都有 `#batchBtn`，且都在点击时先 `pause()`）。

## 4. 风险与建议

- **最大风险：`马尔科夫链 (g).html` 的常驻 `requestAnimationFrame` 自递归渲染。** 它在加载后无条件每帧重绘 canvas，而 `pause()` 只清 `setInterval`、**停不掉渲染循环**，外部又因闭包无法干预。放进 SPA 的多标签/多面板里，切走的 iframe 仍在烧 CPU；来回切换若不销毁 iframe，帧率成本会叠加。建议：SPA 侧在面板隐藏时**销毁 iframe（`iframe.src = 'about:blank'` 或移除节点）**，而不是用 `display:none` 藏起来；或在动画文件里加「循环开关」的最小补丁。
- **高分屏会明显发虚的两个动画（无 canvas 像素级 resize 处理）**：`clt`（`中心极限定理(g).html`）与 `markov-chain` 只在 `window.resize` 时调用 `render(currentN)` / `computePositions()`，**不重设 `canvas.width/height`**，canvas 位图分辨率永远是首帧值（`markov-chain` 的标签上硬编码 `width="820" height="600"`），CSS 只把位图拉伸；`recsys-markov` 则在 `window.resize` 时只调 `drawGraph()`（`drawGraph` 内部会走 `resizeCanvas()`，故实际可自愈）。其余 5 个（`buffon-needle`、`rv-transform`、`marginal-continuous`、`network-traffic`、且 `recsys-markov` 亦然）都通过 `resizeCanvas()` + `devicePixelRatio` 重设位图，缩放后清晰。若 SPA 允许在宽屏 iframe 里二次放大，建议对 `clt` / `markov-chain` 做「重设 `canvas.width/height`」的最小补丁。
- **布局尺寸：需要宽 iframe，且整体很高。** 所有页 `.page` 为 `min(1280–1400px, 96vw)`，主区一律双栏（`grid-template-columns:1fr 410~430px`），断点普遍在 1000–1180px —— iframe 宽度低于约 1120px 会掉成单列，课堂演示观感变差。画布高度：`markov-chain` 600px、`buffon-needle` 520px、`recsys-markov` 520px、`rv-transform` 3×330px、`clt` 双图、`marginal-continuous` 曲面+两张小图、`network-traffic` 470px 舞台 + 2×180px 图表；再加 hero、图例、4 张说明卡、统计面板、`recsys-markov` 的可编辑矩阵表，整页高度普遍在 2000–3000px。**建议 SPA 用「独立可滚动页面/全屏抽屉」承载，不要塞进固定高度卡片**。
- **`file://` 与 http 源的取舍。** 8 个动画本身零外部依赖，`file://` 双击即可运行；但**控制协议只在 http(s) 同源下成立**——`file://` 页面之间互为 opaque origin，`iframe.contentDocument` 会直接失败。因此「能看」与「能控」不是同一套部署前提：本地演示包可继续用 `file://`（此时 adapter 只能降级为纯展示 + 直接打开），要启用统一控制面板必须走静态服务器。
- **隐藏/零尺寸 iframe 会让首帧画成空白。** 多个动画在加载时就 `draw()/render()/drawCharts()`，内部用 `getBoundingClientRect()` 取值并据此设置 canvas 位图尺寸。若 iframe 初始为 `display:none` 或宽度 0，canvas 会被设成 0×0，图表/曲线全空，直到用户手动改变窗口大小才恢复。建议：**先让 iframe 可见（或至少给定非零尺寸）再设 `src`**，展示时主动 `iframe.contentWindow.dispatchEvent(new Event('resize'))` 兜底一次（对 5 个有 resize 重绘的文件能立刻自愈）。
- **`#id` 在 iframe 内不冲突，可安全并存。** 8 个文件的 id 集合不重叠（`#playBtn`/`#startBtn`/`#lambdaRange` 等各自独立作用域），同一个 SPA 页面同时挂多个 iframe 不会互相抢 id；但仍建议**一个可见面板只保留一个活动 iframe**，避免上一条的 CPU 与内存叠加问题。`network-traffic` 还有一处细节：它用 `getBoundingClientRect()` 计算 `.buffer`、舞台坐标来摆放数据包 DOM 节点，iframe 尺寸突变（如动画式展开面板）时若没有触发 resize，包的位置会错位——展开动画结束后补派发一次 resize 即可。

## 附：勘测口径说明

- `canvasCount` 为文件中 `<canvas>` 标签的实测数量（`bayes` 为 0，它用 DOM 圆点 + CSS `conic-gradient` 圆环实现，没有 canvas）。
- `params` 只收录**会改变仿真/视觉结果**的用户输入，按给定 schema 的 5 种类型归类；`markov-chain` 的「箭头显示 全部」是 checkbox，不在 schema 允许的类型内，故未收录；`markov-chain` 的「状态名称」文本框只影响标签文字、不影响仿真，未收录。
- `readouts` 取自各动画面板中**实际带 id、由脚本实时写入**的数值元素。
- `chapter` 为最贴近的课本章节；`markov-chain` 与 `recsys-markov` 的转移矩阵/随机游走内容在课程体系中更接近随机过程专题，这里按「随机变量与分布」的知识落点归入 `ch02`，供章节筛选参考。
- `accent` 优先取该动画自身 CSS 中已使用的主色变量（如 `贝叶斯` 的 `--blue-600:#1e88e5`、`布丰投针` 的相交针色 `#57b947`、`马尔科夫链`/`推荐系统` 的 `--blue:#1F4E79`、`连续型边缘分布` 的 `--purple:#7b61ff`、`随机变量变换` 的 `--orange:#f28c28`），以保证卡片强调色与动画内部视觉一致。
