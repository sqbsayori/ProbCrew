## #1 CPython `re` 编译器偶发 `ValueError: not enough values to unpack`

**状态**：上游缺陷，未复现，已规避风险
**发现时间**：2026-09-11（提交 `bb1eb2c` 之后的一次回归测试中）
**影响面**：低（工具链；未在服务运行时观察到）

### 现象

`python scripts/smoke_test.py` 在一次运行中以退出码 1 结束，stderr 末尾为：

```
    if q - p == 1:
       ^
ValueError: not enough values to unpack (expected 2, got 0)
```

前 25 项检查全部输出 `✔`，异常发生在收尾阶段。

### 排查过程

| 步骤 | 结论 |
|------|------|
| 在 `our-system/` 全库搜 `q - p == 1` | 无匹配 |
| 在 `site-packages`（含 sympy / langgraph / pydantic）全搜 | 无匹配 |
| 在标准库 `Lib/` 全搜 | **命中 `Lib/re/_compiler.py:326`** |
| 读该处代码 | 位于 `_optimize_charset()` 的字符集「连续段压缩」逻辑中 |
| 复现尝试 | `scripts/repro_re_bug.py`：18 个模式 × 8 种 flag × 60 轮 = **8640 次编译，未复现** |
| 连续跑 9 次完整测试 + 3 轮组合命令 | 全部通过 |

### 结论

异常来自 **CPython 标准库 `re` 模块的编译期字符集优化器**，
不是本项目代码，也不是任何依赖的代码。

触发条件是编译某个字符类正则（`[...]`）时，优化器内部的
`runs` 列表出现了非预期的元素。该函数服务于「把字符集压缩成更紧凑的表示」
这一优化路径，与匹配逻辑无关。

**为什么只出现一次**：该路径只在特定字符集形状下走到
（较大的、需要压缩的字符集），且编译结果被 `re._cache` 缓存，
因此同一个模式在一个进程里通常只编译一次 —— 意味着这是
**低概率 + 一次性**的事件，天然难以复现。

### 影响评估

- **服务运行期**：如果发生，会在编译某个正则时抛 `ValueError`。
  表现为单次请求 500，重启后自愈（缓存清空）。不会损坏数据。
- **CI**：会让 `smoke_test.py` 偶发红灯。这是唯一比较烦人的地方。
- **已有缓解**：所有正则调用点都写在函数内部（每次调用才编译，
  走 `re` 模块的缓存），没有模块级 `re.compile()` 的全局状态被破坏的风险。

### 建议处置

1. **不要修改标准库**。这是上游问题修正的正确归属。
2. 若 CI 里再次出现且难以忍受，加一次重试即可（本项目暂不做，
   因为一次重试会掩盖真实失败）。
3. 升级 Python 小版本（3.11.8+ / 3.12+）时可以用
   `python scripts/repro_re_bug.py` 再验一次。
4. 若在服务运行期再次观察到，请记录：**完整的 traceback + 触发时的请求**，
   这两个信息才能定位到具体是哪个正则。

### 相关文件

- 首次观察：`scripts/smoke_test.py`（第 6 节 SymPy 检查之后）
