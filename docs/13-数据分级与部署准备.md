# 13 · 数据分级与部署准备

> 本文落实三条会议/沟通决定：
> **① 后端先跑本地，但按"随时能上服务器"的标准写；② 数据分三级，敏感数据只在本地库；③ 模型调用导致的数据外流暂不作为决策依据。**
>
> 第 ③ 条的含义要说清楚：它**取消了"因为怕数据外流所以不能做某功能"这条否决理由**，
> 但**没有取消"敏感数据要分级存放"这个工程要求** —— 两者是不同层面的事。

---

## 一、数据分级（三级）

分级的判据只有两条：**能不能公开**、**泄露了会不会伤害到具体的人**。

| 级别 | 名称 | 内容 | 存放位置 | 能否出校 | 能否进公开发布包 |
|---|---|---|---|---|---|
| **L0** | 公开数据 | 自写知识库、开源数据集、公开例题、8 个动画 | 仓库内 / 任意 | ✅ | ✅ |
| **L1** | 校内数据 | 教材电子版、教学大纲、历年习题与答案、知识点依赖树、常见错误清单 | 服务器本地磁盘 | 仅校内服务可访问 | ❌ |
| **L2** | 敏感数据 | 学生作答记录、学号/姓名、成绩、问答日志（含提问原文） | **仅本地库**；若上服务器，必须加密且与 L1 物理/逻辑隔离 | ❌ | ❌ |

### 1.1 现在就要落地的两条硬约束

**约束 1：L2 永远不进代码仓库。** 不是"小心别提交"，而是**结构上不可能提交**：

- 数据库文件放 `backend/data/`，且 `.gitignore` 必须包含 `backend/data/`
- 环境变量/密钥放 `.env`，已在 `.gitignore`；仓库里只有 `.env.example`
- **CI 已有密钥扫描**（全历史），但扫描规则要**补一条**：`*.sqlite` / `*.db` / `学生` / `学号`
  等文件名与内容的探测（防止有人把导出文件塞进仓库）

**约束 2：L2 表结构必须以 `student_` 前缀命名。**
这样"哪些表敏感"是**可机械判定**的，不靠记忆：以后写导出脚本、备份脚本、日志脚本时，
一条 `LIKE 'student_%'` 就能把敏感表全部排除。

### 1.2 现状核对

| 项 | 现状 | 需要做什么 |
|---|---|---|
| 学习记录库 | `backend/data/learning.sqlite`（`tools/learning_log.py`） | ✅ 路径已正确（不在仓库内）；⚠️ 但 **B 线挂起后这张表是否还写**要定 |
| 密钥 | `.env`（工作区根），已 gitignore | ✅ |
| 知识库（L0/L1 混放） | `backend/knowledge_base/*.md` 在仓库里 | ⚠️ 换成**教材原文**后必须移出仓库，改放 `backend/data/corpus/` |
| 学生数据 | 尚无 | 现在不建表；等 B 线激活再建，且用 `student_` 前缀 |

**这里有个立刻要做的动作**：`knowledge_base/` 现在放的是我们**自写**的 L0 内容，没问题。
但一旦把**本校教材电子版**放进去（B1，会议已明确要问老师要），它就是 L1，**必须移出仓库**。
建议现在就把读取路径设计成"仓库内的示例语料 + 仓库外的正式语料"两个来源，
免得以后临时改代码。

## 二、部署准备（本地优先，服务器就绪）

原则：**一套代码、两种环境**，靠配置切换，**不靠改源码**。

### 2.1 环境矩阵

| | 开发环境（现在） | 目标环境（后期） |
|---|---|---|
| 后端地址 | `http://127.0.0.1:8000` | `https://probstat.<某域名>` |
| 前端资源 | 后端一并托管 | 同左（或 CDN，但需保持同源） |
| 数据库 | 本地 SQLite | 服务器 SQLite 起步，必要时转 Postgres |
| 密钥 | `.env` 文件 | 环境变量注入（不落盘） |
| HTTPS | 不需要 | **必须**（油猴/扩展在 https 页面注入 http 后端会被拦） |

### 2.2 必须现在就修掉的硬编码（否则后期要改所有人的脚本）✅ 已完成

**原问题（已核实）**：`frontend/widget/probstat-assistant.user.js` 里

```js
var API_BASE = 'http://127.0.0.1:8000';          // ← 写死
// @require http://127.0.0.1:8000/widget/api.js  // ← 7 行全部写死
```

后果：部署到服务器后，**每个学生装的脚本都要改源码重装**。这是最不该付的代价。

**修法（三层地址解析，优先级从高到低）**：

1. 脚本顶部留一个**配置块**（学生只需改这一处），或更好：
2. **`@require` 用相对路径**（`/widget/api.js`），由 Tampermonkey 按"脚本安装来源域名"解析
   —— 学生从发布页安装，地址自动正确，**永远不用改源码**
3. `API_BASE` 兜底顺序：`data-api` 属性 → `location.origin`（本页同源）→ 配置块 → 报错并给出人话提示

**实际落地**（比原计划多两层，因为"推断失败"必须能被解释）：

| 层 | 取值 | 什么时候命中 |
|---|---|---|
| ① | 本页 `<html data-api="...">` | 宿主页自己声明了后端 |
| ② | 配置块 `API_BASE_PIN`（源码里**留空**） | 前后端分域部署，由生成器写入发布物 |
| ③ | `location.origin` | 后端同时托管前端（同源，主路径） |
| ④ | `GM_info` 的安装来源 URL / 绝对 `@require` | 目标页是 `file://` 等推断不出同源时 |
| ⑤ | —— | 全部失败 → **控制台显式报错**，给出三种解决办法，绝不静默 |

**对应要做的事**：把"脚本从哪装"变成**发布物**，即部署时自动生成一份内容正确的
`probstat-assistant.user.js`（地址来自配置），而不是让开发者手改
—— 见 `scripts/build_userscript.py`（源码保持通用，只有分域/file:// 场景才需要生成发布物）。

**进度**：✅ 已完成（2026-09）。仓库源码里已无任何写死的后端地址；
`scripts/check_contracts.py` 第 6 节 + `frontend/widget/_test_deploy.mjs` 会拦住回退。

### 2.3 后端要做的环境无关化改造 ✅ 已完成

| 项 | 改造前 | 现在 |
|---|---|---|
| 监听地址 | `127.0.0.1:8000`（`启动.bat` 写死） | 由 `.env` 的 `APP_HOST` / `APP_PORT` 控制；`启动.bat` / `start.sh` 都从 `.env` 读，服务器上设 `0.0.0.0` |
| CORS | `allow_origins=["*"]`（代码里写死） | 由 `CORS_ORIGINS` 读（逗号分隔），本地默认仍是 `*`，一行配置即可收窄；`*` 与 `allow_credentials` 的无效组合会被自动关掉 |
| 配置来源 | `Settings`（pydantic-settings，已支持 `.env` 与根级 `.env`） | ✅ 补上 `app_host/app_port/cors_origins/db_path/db_url` |
| 日志 | 无结构化日志 | ⏳ 上线前要加：谁在什么时候问了什么（**注意：提问原文属 L2**） |
| 健康检查 | ✅ `/api/health` | ✅ 已补：数据库连通性 + 语料条数 + 当前部署参数（host/port/CORS） |
| 静态资源 | 后端挂载 `frontend/` | 保持同源（避开跨域与 cookie 问题） |

**注意一个容易忽略的点**：前端目前由后端挂载在同一端口，
所以 `loader.js` 的 `data-api=""`（同源）是能用的。
一旦前后端分域部署，**同源假设就破了**，CORS 与 https/http 混用会立刻出问题。
**建议：保持同源部署**（后端同时托管前端），代价最小；
真要分域，则用 `frontend/index.html` 的 `__PSA_API__` 配置块 + `CORS_ORIGINS` 白名单。

### 2.4 上线前检查清单（等要部署时逐条过）

- [ ] `APP_HOST=0.0.0.0`，端口不冲突，进程守护（systemd / supervisor）
- [ ] HTTPS 证书（**必须**，否则第三方 https 页面注入会被拦）
- [ ] CORS 白名单收窄（去掉 `*`）
- [ ] `.env` 不进镜像、不进仓库；密钥由环境注入
- [ ] `backend/data/` 有备份策略，**且备份文件不落公网**
- [ ] 密钥扫描规则补充：数据库文件、导出文件
- [ ] 语料（L1）与仓库分离，部署时单独同步
- [ ] 日志脱敏：L2 字段不写进普通日志
- [ ] 域名备案（如需对外，周期长，**越早启动越好**）

## 三、这份文档对"程序编写"的直接约束

写代码时只需要记住四条：

1. **不要在任何前端代码里写死后端地址** —— 一律走配置（`data-api` → `location.origin` → 配置块）
2. **语料/数据读路径要可配置** —— 仓库内示例 + 仓库外正式，两来源
3. **敏感表用 `student_` 前缀** —— 便于机械排除
4. **本地能跑 ≠ 可以不写配置** —— 服务器环境的差异（host/port/https/CORS）全部通过配置表达

> 本阶段（M1/M2，即页面助手核心 + 检索升级）**完全不涉及 L2 敏感数据**：
> 不需要学生数据，也不需要建任何学生表。可以放心开工，不必等数据授权。
