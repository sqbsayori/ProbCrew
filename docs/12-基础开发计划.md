# 12 · 基础开发计划

> 目标产品一句话：**一个能读懂学生正在看的那个网页、并能被验证的辅助学习工具。**
>
> 交付形态一句话：**同一套前端代码，既可以被注入进别人页面，也可以作为独立脚本从外部读取任意页面。**

---

## 一、先把"两个形态"说清楚

这是本计划最容易被误解的地方，必须先定义。

| | 形态 A · 页面内助手 | 形态 B · 独立外部助手 |
|---|---|---|
| **运行位置** | 目标页面**内部**（与课件同一文档树） | 目标页面**之外**（浏览器扩展侧边栏 / 用户主动粘贴 / 外部窗口） |
| **投递方式** | ① 自建站一行 `<script>`<br>② 第三方平台：油猴脚本 / 浏览器扩展 content script | ③ 浏览器扩展（side panel）<br>④ 独立网页：粘贴链接或正文 |
| **读页面的手段** | 直接访问 DOM（同源/同文档） | 需要**授权**：content script 注入 或 用户手动提供内容 |
| **能读到什么** | 正文、标题、公式、选区、视频进度、动画状态、跨 iframe | 同上（经 content script 后等价） |
| **优势** | 体验最好：划词、跟随、动画联动 | 平台完全零依赖：连注入都不需要 |

**关键结论**：

> **两种形态共用同一套"读取 + 推理"内核，只有"投递与授权"不同。**
> 所以架构上只需要做一件事：把**页面读取层**做成独立、可替换的模块；
> 上层（面板 UI、编排、验证）完全不用感知自己是"被注入"还是"从外部接入"。

**必须诚实说明的一条限制**：

> 任何"从外部读取网页内容"的方案，**都必须先获得该页面的执行权限**（注入 content script 或用户手动提供）。
> 纯前端跨域读别人的页面在浏览器里**做不到**（同源策略），这不是实现问题，是浏览器安全模型。
> 所以形态 B 的准确表述是"**独立入口 + 一次性授权**"，而不是"隔空抓取"。

## 二、产品要解决的三个真问题（按优先级）

功能不是列举出来的，是从问题倒推的。这个工具只在三种情况下有价值：

| 优先级 | 学生的问题 | 我们的做法 | 现状 |
|---|---|---|---|
| **P0** | "这一段在说什么？" | **划词/选中 → 结合当前页面上下文解释** | 已实现（`page_tutor` + `extractor`） |
| **P0** | "这题怎么做？答案对不对？" | 解题 + **独立校验**，并标注**可信级别** | 已实现（`solver` + `verifier`，需加固） |
| **P1** | "课件里没讲清楚，教材上怎么说？" | 检索**本校教材**并引用出处 | 有骨架（`kb_search` 是关键词匹配，**待升级**） |
| **P1** | "我学到哪了 / 我哪里薄弱？" | 读页面进度；记录问答轨迹 | 部分（读进度已实现；薄弱分析依赖 B 线，**挂起**） |
| **P2** | "这个动画在演示什么？" | 读取动画状态 → 单步 + 讲解 | 已实现（`anim-bridge`） |

**不做**（会议已定）：拍照批改（多模态）、自建视频素材、自训练模型、学生建模与教师端（挂起）。

## 三、架构：三层解耦

```
┌──────────────────────────────────────────────────────────┐
│ ③ 交付层 Delivery        loader.js / user.js / extension  │  ← 只负责"怎么进来"
├──────────────────────────────────────────────────────────┤
│ ② 助手层 Assistant       assistant.js（面板·页宠·会话）    │  ← 产品体验，不感知来源
├──────────────────────────────────────────────────────────┤
│ ① 上下文层 Context       extractor / frames / anim-bridge │  ← 只负责"看到什么"
└──────────────────────────────────────────────────────────┘
                              │  SSE（契约：contracts/events.schema.json）
                              ▼
┌──────────────────────────────────────────────────────────┐
│ 后端 Backend                                             │
│   kernel/   编排图 · 事件 · 注册表 · HITL 闸门            │
│   agents/   orchestrator → (page_tutor | knowledge |      │
│             solver) → verifier → hitl                    │
│   tools/    kb_search（检索）· math_tools（SymPy 校验）    │
│   providers/ DeepSeek ｜ mock（离线/CI）                  │
└──────────────────────────────────────────────────────────┘
```

**三条硬约束（决定协作不会互相踩）**：

1. **交付层不碰上下文层**：加一种投递方式（比如浏览器扩展），不改 `extractor`。
2. **上下文层不碰后端**：`extractor` 只产出一个 `FrameContext` 对象（`contracts/page-context.schema.json`）。
3. **前后端只通过事件协议通信**：14 种事件类型，**只增不改**。

## 四、开发阶段（按依赖排序，不排日期）

### M0 · 骨架剪枝（前置，必须最先做）

- **做什么**：按 `docs/11-骨架剪枝清单.md` 执行；删展示页，保留 `widget/` + `kernel/` + 检索/校验工具
- **产出**：可开工的默认分支
- **完成标准**：
  - 新人 `git clone` → `启动.bat` → **5 分钟内**看到悬浮窗并成功提问一次
  - 契约 / 冒烟 / 单测 / 两个 .mjs 测试全绿
  - 旧演示可由 tag `v0.1.0-prototype` 找回

### M1 · 核心可用（页面内助手真正好用）

- **做什么**：
  1. **抽取质量加固**：正文识别在 5 类真实课件页上不跑偏（纯文本页 / 多 iframe / 表格多 / 公式多 / 侧栏干扰重）
  2. **划词闭环打磨**：选区 → 解释 → 追问 → 引用页码/段落
  3. **页面内检索**：选中内容 + 页内其他段落互证（`page_tools` 已有，补精度）
  4. **SSE 断线/超时处理**：后端没起、Key 失效、请求超时都要给**人话提示**，不能白屏
- **完成标准**：在真实课件页上完成 10 次真实提问，**不需要开发者介入**
- **风险**：抽不到正文时可能沉默 → 必须**显式警告**（沿用现有设计：读不到就报警，不装作读到了）

### M2 · 检索升级（最高杠杆的一步）✅ 已完成

- **做什么**：
  1. 接入中文嵌入（**BGE-M3** 或 `bge-large-zh-v1.5`），替换/叠加现有 BM25 关键词检索
  2. 接入重排（**bge-reranker-v2-m3**）
  3. **混合检索**：BM25 + 向量，因为 **BGE-M3 对 LaTeX 效果弱**，而我们的教材全是公式
  4. 检索结果带**出处**（章节 / 小节），在前端可点开
- **为什么优先**：**每个 Agent 都要调检索**，这是整条链的地基；且它是"答得准"的最大变量
- **完成标准**：同一批 ≥30 个问题，**升级前 vs 升级后**的 top-3 命中率对比数据（写进文档）
- **数据不出校**：嵌入与重排模型**全部本地跑**，教材原文不进任何第三方 API

**实现与验收（2026-09）**：

| 项 | 位置 |
|---|---|
| 嵌入层（BGE-M3，本地权重；缺权重时降级并**显式标注**） | `backend/app/tools/embedding.py` |
| 重排层（bge-reranker-v2-m3；不可用返回原因） | `backend/app/tools/reranker.py` |
| 混合检索（BM25 + 向量，加权 RRF；出处含章/小节/行号/片段） | `backend/app/tools/kb_search.py` |
| 权重安装 / 缺文件补齐 | `scripts/setup_models.py`、`scripts/repair_model_cache.py` |
| 对比脚本 + 40 题标尺 | `scripts/eval_retrieval.py`、`scripts/retrieval_questions.tsv` |
| **对比数据（真实权重）** | **`docs/16-检索升级对比.md`**（每次重跑覆盖） |
| 回归测试 | `backend/tests/test_retrieval.py` |

**40 题实测（top-1 按小节从 76.5% → 85.3%，top-3 按章四种配置均 97.5%）**：

| 配置 | top-1 按章 | top-3 按章 | top-1 按小节 | 单次耗时 |
|---|---|---|---|---|
| 仅 BM25（升级前基线） | 85.0% | 97.5% | 76.5% | 0.9 ms |
| 仅向量（BGE-M3） | 90.0% | 97.5% | 85.3% | 70 ms |
| 混合（融合，不重排） | 92.5% | 97.5% | 82.4% | 75 ms |
| 混合 + 重排 | 90.0% | 97.5% | 85.3% | 2243 ms |

**三条从实测得到的结论（写进计划，避免后人重走）**：
1. **BM25 必须留**：小语料上 BM25 的 top-3 按章已 97.5%，纯向量并没有压倒性优势；
2. **融合方式比"用不用向量"更关键**：min-max 归一化加权平均与纯 RRF(K=60) 都让 top-1 下降，
   最终用**加权 RRF（K=10）+ 同路幅度加成**；
3. **重排在 CPU 上很贵**（≈2.2 s/次）而本轮精度收益有限 → 交互路径默认「融合不重排」，
   重排用于离线评估 / 批量整理，可用 `RERANK_CANDIDATES` 调成本。

### M3 · 可信答案（本项目的差异化）

- **做什么**：
  1. **分级**：A 数值（SymPy 复算，可完全验证）/ B 符号（等价性）/ C 应用题（多路径 + 约束 + 反向代入）/ D 证明（**不声称已校验**）
  2. **多路径交叉**：同一题独立解 ≥2 条路；**结论不一致时触发辩论，不做投票**
  3. **强制校验报告**：任何答案都必须附校验结论，**不允许出现"裸答案"**
  4. **HITL 闸门**：高风险结论（解题）必须人工确认才落定
- **完成标准**：随机抽 20 道题，**每条答案都能回答"这个结论经过了几层验证、哪层没过"**
- **红线**：绝不出现"已校验"这种模糊表述；没验证就写没验证

### M4 · 自制评测基准（因为没有真题）

- **做什么**：**C1 概率论基准** ≥100 道（题目 + 标准答案 + 知识点标注）
- **硬要求**：**逐题用 SymPy 独立复算**；答案不一致的必须标出并人工裁定
- **为什么必须自制**：历年真题暂时拿不到 → **M4 是唯一能证明"我们变好了"的东西**
- **完成标准**：跑出一份基准确率报告，成为后续所有改动的回归基准

### M5 · 外部形态（形态 B）+ 真实平台验证

- **做什么**：
  1. **真实智慧树平台验证**：装油猴脚本，走一遍真实课件（**这是当前最大的未知数**）
  2. **浏览器扩展**（Manifest V3）：content script 注入 + side panel，解决形态 B 的授权问题
  3. **宿主页无关化**：确认助手在非本站域名下不依赖任何本站资源（除 `data-api` 指向的后端）
- **风险点（必须先假设会失败）**：平台 CSP、iframe 域名隔离、课件页非常规 DOM
- **完成标准**：至少 1 个真实平台的 1 个真实课件上跑通

### M6 · 后续可选（不阻塞主线）

- 知识点依赖树（DAG）：用于"薄弱根源定位"，**依赖内容入库**
- 常见错误清单（C4）：提升"讲清为什么错"的质量
- 学习记录 / 薄弱分析：**依赖 B 线，挂起**
- 多模态拍照批改：**待老师明确方案 + 数据安全方案**

## 五、第一个版本的定义（M0 + M1 完成 = 可交付）

**用户能做的事**：

1. 打开一个课程页面，右下角出现页宠/悬浮球
2. 划选一段文字 → 弹出「解释这段」→ 得到结合上下文的解释
3. 直接在面板里提问 → 得到流式答案，带**校验级别标注**
4. 打开侧栏的「📖」可随时关闭页面读取（隐私可控）
5. 读不到内容时，面板**明确显示**读不到及原因

**开发者能做的事**：

1. 加一个 Agent：新建 `backend/app/agents/xxx.py`（`SPEC` + `run()`），**自动被发现**
2. 加一个工具：新建 `backend/app/tools/xxx.py`（`@tool`），**自动被发现**
3. 加一种投递方式：只写交付层，**不动 `extractor` 与后端**
4. 契约校验 + 4 组测试在 CI 里拦住回归

## 六、风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| **真实平台注入失败**（CSP / 跨域 iframe） | ★★★ 最高 | **M5 提前做一次最小验证**，不要等到最后才发现路走不通 |
| 抽取质量不稳（不同课件页结构差异大） | ★★ | 建立"5 类典型页面"回归集，抽取结果**可人工核对**（沿用现有活体探针思路） |
| 检索升级后**反而变差**（LaTeX 被嵌入模型忽略） | ★★ | 必须保留 BM25 混合；升级前后用同一批问题对比 |
| 学生数据敏感 / 教材版权 | ★★ | 数据不出校；教材仅校内使用，**不公开分发**；不采集学生原始数据 |
| 范围再次膨胀（又想做多模态/学生建模） | ★★ | 本文档"不做清单"写在最前面；新需求一律进 M6 排队 |
| 只有一个人能合并 PR（无 review） | ★ | 走交叉审查（给 2 人以上 write 权限），或明确接受负责人自合并 |

## 七、工程约定（不排日期，只定规则）

- **分支**：`feature/xxx` →（squash）`dev` →（merge）`main`。**绝不 squash `dev`**（会分叉历史，踩过）
- **契约只增不改**：改字段必须走 ADR；`contracts/api.md` 由脚本生成，禁手工编辑
- **自动发现优先**：加功能只动自己目录，**不改公共文件** —— 这是并行开发不打架的关键
- **不修改他人素材**：8 个原始动画文件**一字不改**（需要注入时由后端在响应时插）
- **失败必须显式**：读不到内容、检索为空、校验不过 —— 都要说出来，**不允许沉默降级**
- **测试是门槛不是装饰**：新增能力必须带一个能拦住回归的测试

## 八、需要团队立刻想清楚的一个问题

**这个工具到底服务"概率论这一门课"，还是"任何在线课程"？**

- 现在所有内容资产（知识库、例题、分布模块、8 个动画）都是概率论的；
- 但架构（抽取 + 检索 + 校验）**本身是学科无关的**；
- 建议口径：**架构按通用做，内容先做透概率论一门课**。
  理由：内容决定上限，架构决定能不能扩展。先把一门课做到"学生真的愿意用"，
  比铺开五门课、门门都不准要有价值得多。
