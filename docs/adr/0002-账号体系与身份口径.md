# ADR-0002 · 引入账号体系：身份口径从「匿名 session」改为「账号」

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：项目负责人（R1）
- **相关**：`contracts/CHANGELOG.md` v1.4 · `contracts/user.schema.json` · `docs/13` · `docs/21` · `docs/22`

---

## 背景

在此之前的整个原型是**无账号**的：身份 = 浏览器本地生成的匿名 `session_id`
（`probstat.session_id`），后端把 `session_id` 当数据归属键。
`docs/22` 甚至把这一点当作已满足的非功能需求（`N6 无 PII ✅`），
`docs/21 §5.2` 也明确规定 `attempt.student_id` **填 `session_id` 同值**。

现在要支持**多账号**与**两种角色**（学生 / 管理员），并让学生数据管理页可用。
这个需求本身来自立项书（`docs/15 §2.2` 认领的"JWT 鉴权 + 角色权限矩阵 ❌"），
所以是**主动推翻**先前"无用户系统"的口径，而不是遗漏。

---

## 决策

### 1. 身份只来自令牌，路径参数不再决定归属

- 登录：`POST /api/auth/login` → **服务端会话令牌**（不是 JWT）。
- 令牌：`secrets.token_urlsafe(32)`，**库里只存 sha256**，7 天有效。
- 请求：`Authorization: Bearer <token>`；除 `/api/health`、`/api/auth/login` 与静态资源外，
  全部端点要求登录。
- **旧路径**（`/api/wrong/{session_id}`、`/api/stats/{session_id}`）保留 URL 形状，
  但**忽略路径参数**，身份一律以令牌为准。

**为什么不用 JWT**：JWT 是无状态的，无法满足"重置密码 / 禁用账号后**立刻**失效"。
课程场景里"老师把某个账号停掉"必须是即时生效的。

**为什么必须改路径参数**：旧实现把 `session_id` 当身份，
`GET /api/wrong/随便一个人` 返回 200（实测），`GET /api/runs` 会明文列出**所有人**的提问原文。

### 2. 数据归属改为 `user_id`，老数据迁移到一个不可登录的历史账号

- 三张业务表加 `user_id`，并统一改为 `student_` 前缀（`docs/13 §1.1 约束 2`：L2 表必须可机械识别）。
- `student_mastery` 主键由 `(session_id, topic)` 改为 `(user_id, topic)`
  —— 同一个人换浏览器就是另一个 session，按 session 聚合会把掌握度拆成几份。
- 老数据全部归属到 `usr_history`（`username='history'`、**空哈希 + disabled**，任何密码都登不进去），
  迁完把老表改名为 `legacy_*` 保留一周。

### 3. 只能管学生，且不能自锁

- 管理端接口与 CSV 导入**都无法创建管理员**（`role` 写死为 student）；
  管理员账号只由种子流程（首次启动）或 `scripts/manage_users.py` 产生。
- 管理员不能禁用/删除自己。
- 看学生明细 / 导出 CSV / 删数据 / 重置密码 / 禁用 —— 全部写审计，**审计写失败即中止操作**。

---

## 后果

**正面**
- 补上了立项书要求的角色与权限矩阵；管理端能回答"学生有没有在学"。
- 顺带修掉三处实测泄漏：`/api/runs` 全量明文、`/api/wrong/{sid}` 越权、`/api/runs/{id}/timeline` 回传完整答案。
- 有了账号，`hint_used` 才真正可用作"是否在抄"的信号（`docs/22` 缺口 3）。

**代价（必须承认）**
1. **这不再是"无 PII"**。缓解：账号为化名（不采集学号/真实姓名）、密码只存 bcrypt 哈希、
   数据仍只落本地库、提供"删除我的数据"入口。口径修正已写进 `docs/22` 与 `原型声明.md`。
2. **悬浮窗不再"打开即用"**。它注入在第三方页面，`localStorage` 与主站不共享 →
   学生要在悬浮窗里再登录一次（`docs/20` 已补记）。
3. **演示环境需要先建号**。首次启动会自动创建种子管理员并把密码打印到启动日志；
   批量建号走 `POST /api/admin/students/import` 或 `scripts/manage_users.py`。
4. **测试与脚本要跟着改**：既有测试原本匿名调用接口，现在通过 `backend/tests/_auth.py`
   统一登录；`scripts/live_test.py` 增加了 `--password` 参数。

---

## 替代方案（为什么没选）

| 方案 | 为什么不选 |
|---|---|
| 继续匿名 + 共享口令 | 无法区分学生，管理端只能看到一堆互不相干的 session，`hint_used` 也无从归属 |
| JWT（无状态令牌） | 无法即时吊销；"禁用账号后旧令牌还能用"是硬伤 |
| Cookie 会话 | 悬浮窗跨域要 `SameSite=None; Secure`，本地 http 调试直接不通 |
| 自建用户表 + 明文/可逆加密密码 | 不可接受 |
| 引入 PostgreSQL + 成熟用户系统 | 对本项目规模是过度工程；SQLite + 自建小表足够，且换实现只改 `accounts.py` |
