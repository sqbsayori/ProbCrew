# ADR-0003 · 前端共享内核与生成式产物（对 ADR-0001 的最小补充）

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：项目负责人
- **相关**：`docs/23-前端技术栈口径.md`（口径正文）· `docs/adr/0001`（免构建 ESM）· `docs/20`（悬浮窗最终形态）

---

## 背景

前端存在**两套加载方式**，且这是**约束决定的，不是历史遗留**：

- 主站 SPA 用原生 ESM（`frontend/app/`，25 个文件用 `import`/`export`）；
- 悬浮窗用经典脚本 IIFE + `window.__PSA`（`frontend/widget/`，12 个文件**零 ESM**），
  因为油猴 `@require` 只接受经典脚本，而它"安装期抓取、运行时不受目标站点 CSP 限制"的能力
  正是我们能在第三方课程平台上工作的前提。

代价是**同一段逻辑写了两遍**，而且已经漂移（实测）：

| 重复内容 | 证据 |
|---|---|
| SSE 帧解析 | `app/core/api.js:71` ↔ `widget/api.js:83`（一个 async-for、一个 promise-pump） |
| Markdown + KaTeX | `app/components/{markdown,katex}.js` 263 行 ↔ `widget/render.js` 348 行（`normalizeMath` 逐字同逻辑两种写法） |
| API 客户端形状 | 40 个具名封装 ↔ 6 个通用函数 |
| 事件类型知识 | `trace.js` 13 个 case / `assistant.js` 11 个（契约里 14 种） |
| 设计 token | `tokens.css` 是主站来源；`widget.css` 零变量、77 处硬编码色值（13 种与 tokens 同值） |

两个形态之间**零共享文件** —— 同一个 bug 要修两处，修一处另一处静默不一致。

---

## 决策

采用「**共享内核（canonical ESM）+ 生成式经典脚本产物**」：

1. 新增 `frontend/shared/`（ESM，纯逻辑，禁止触碰 DOM/`window`/`fetch`），作为跨形态逻辑的唯一真相来源；
2. 主站直接 `import` 它；
3. 悬浮窗**不改模块格式**，而是消费由 `scripts/build_widget.py`（**纯 Python 标准库**）生成的
   `frontend/widget/_shared.js`（经典脚本包）与 `_modules.json`（加载清单）；
4. 产物**提交进仓库**，CI 用 `--check` 校验新鲜度 ——
   与既有的 `gen_api_contract.py`（`contracts/api.md`）、`gen_registry.py`（`features.registry.js`）**完全同一套做法**。

---

## 与 ADR-0001 的关系（**ADR-0001 仍然成立**）

| ADR-0001 的承诺 | 本决策后 |
|---|---|
| 无 npm / 无 `node_modules` | ✅ 不变（生成器只用 Python 标准库） |
| 无打包器 | ✅ 不变（没有引入 Vite/Webpack/Rollup/esbuild） |
| 改完刷新即生效 | ✅ 不变（主站仍是 ESM，无需构建；只有 widget 需要跑一次生成） |
| 离线可用、静态托管 | ✅ 不变（产物是普通文件，随前端一起托管） |
| 新人上手成本低 | ⚠️ 略增：多一条"改了 `shared/` 要跑生成器"的规则；由 CI 红灯保证不会被忘 |

**唯一的例外**：为了跨形态共享，允许一个**确定性的、纯 Python 的拼接步骤**。
它的输入输出都进版本库、可人工审阅、可重复生成 —— 这是它与"打包器"的本质区别。

---

## 后果

**正面**
- 同一逻辑只有一份实现，"修一处漏一处"的可能性消失；
- 设计 token、事件常量、SSE 协议都收敛到单一来源，主题与协议变更只需改一处；
- `@require` 的模块清单不再手写（由 `_modules.json` 生成并校验），改名漏改的坑消失；
- 新增一条**等价性测试**作为哨兵：同一输入喂给两侧，输出必须逐字相同。

**代价**
- 多一个生成步骤与一条 CI 门禁（`build_widget.py --check`）；
- 仓库里多两个生成产物文件（`_shared.js` 约几百行、`_modules.json` 很小）；
- 手写拼接器天生脆弱 → 用严格输入约束（相对导入、具名导出、无循环、无顶层 await、不碰 DOM）
  + "遇到不支持语法立即报错" + `--check` 门禁 + 等价性测试四道保险压住。

---

## 替代方案（为什么没选）

| 方案 | 否决理由 |
|---|---|
| 悬浮窗也改成 ESM | 只能靠向宿主页面注入 `<script type="module">`，会被宿主 CSP 拦掉 —— 那正是 `@require` 存在的理由（`docs/23 §1.1`） |
| 主站也改回经典脚本 | 放弃动态 import 与模块化，是倒退 |
| 只定规矩、不重构 | 重复继续存在，且已经漂移过（本项目实测） |
| 引 Vite 统一打包 | 与 ADR-0001 的核心承诺冲突，且本项目页面规模不需要 |
| 用 npm 装一个微型打包器 | 把一个"纯 Python 可审的拼接"换成不可审的依赖 |

## 影响面

| 位置 | 改动 |
|---|---|
| `frontend/shared/`（新） | `sse.js` · `markdown.js` · `math.js` · `api.js` · `events.js`（生成） |
| `frontend/widget/` | 删掉 `api.js`/`render.js` 里的重复实现，改为消费 `__PSA.shared`；`loader.js` 读清单；`@require` 加一行 |
| `frontend/app/` | `core/api.js` 与 `components/{markdown,katex}.js` 改为调用/转出共享内核（**对外导出名不变**，页面组零感知） |
| `scripts/` | 新增 `build_widget.py`、`gen_events_js.py`（都带 `--check`） |
| `docs/` | 新增 `docs/23`（口径）与本文；`docs/18` 登记权威；`docs/01` 加指向 |
| CI | 新增两步：生成产物新鲜度、事件常量与契约一致 |
