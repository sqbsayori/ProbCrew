# ADR-0001 · 前端采用免构建 ESM，而非 Next.js

- **状态**：已接受
- **日期**：2026-09-06
- **决策人**：R1（架构）/ R4（前端）

---

## 背景

团队在 `reproduce/math-tutor` 与 `reproduce/eduagents` 中已有 Next.js 复现经验，
直觉上会倾向继续用 Next.js。但本项目有三个硬约束：

1. **要建立在既有 8 个自包含 HTML 动画之上**。这些动画是 vanilla JS + Canvas，零依赖，
   可以直接双击打开。引入打包器会把它们变成"构建产物"，损失可单独分发、可离线、可嵌入数字教材的特性。
2. **需要离线/内网演示**。答辩现场网络不可控，构建链越长，出问题的环节越多。
3. **5 个学生并行开发，且前端不是所有人的强项**。构建工具、依赖版本、`node_modules`
   会迅速成为协作摩擦源（"我这边跑不起来"）。

同时，本项目的 UI 复杂度是可控的：7 个页面、无 SSR/SEO 需求、无复杂状态管理。

---

## 决策

前端采用**原生 ESM + 动态 import**，不引入打包器。

具体做法：

- 浏览器直接加载 `/app/bootstrap.js`（`<script type="module">`）。
- feature 通过**动态 import** 加载：`await import('./features/${dir}/index.js')`，
  目录清单由 `scripts/gen_registry.py` 扫描 `feature.json` 生成。
- 依赖控制在零：KaTeX 用 `vendor/katex/`（本地 1.6MB），
  Markdown 与图表都是自写的小实现（`components/markdown.js`、`components/chart.js`）。
- 公式渲染、Canvas 图表、动画嵌入全部由浏览器原生能力完成。
- 由 FastAPI 的 `StaticFiles` 托管整个 `frontend/`，保证与 `/animations` **同源**
  （这是远程驱动 iframe 内动画按钮的前提，见 ADR-0002）。

---

## 后果

**正面**

- 零安装、零构建：`.\scripts\dev.ps1` 起来就能改，改完刷新浏览器即生效（无 HMR，但改一两个文件时刷新足够快）。
- 与自包含动画的部署方式完全一致 —— 都由静态托管解决，没有构建产物与源码两套东西。
- 新人上手成本极低：会写 HTML/CSS/JS 就能贡献页面。
- 离线可用：断网、内网答辩都不受影响。
- 没有 `node_modules`，仓库轻、CI 快。

**负面**

- **没有 TypeScript 类型检查**。缓解：以 `contracts/events.schema.json` 为契约，
  由 `scripts/smoke_test.py` 第 4 节做运行时校验；同时 `backend/tests` 覆盖内核。
- **没有 HMR**，改样式需要手动刷新。缓解：浏览器 DevTools 里可直接改 CSS 调试。
- **依赖增长后模块图会变复杂**。缓解：禁止 feature 之间互相 import（只走 `core/bus.js`），
  共享代码必须放 `components/` 或 `core/`。
- **无法做 SSR/SEO**。本项目是教学工具，不需要；若未来要做公开门户，见下。

---

## 被否决的备选方案

| 方案 | 否决理由 |
|------|---------|
| Next.js（复用复现经验） | 构建链重、`node_modules` 摩擦大、与自包含动画的托管方式不一致；本项目不需要 SSR |
| Vite + Vue/React | 比 Next.js 轻，但仍引入构建步骤与依赖；7 个页面的规模收益不明显 |
| 单文件大 HTML（沿用 `prototype/index.html`） | 1176 行单文件无法多人并行；这正是本项目要解决的问题 |

---

## 何时重新评估

满足**任一**条件时，重新讨论是否迁移到 Vite / Next.js：

1. `frontend/app/features/` 下模块数 **> 25**；
2. 出现真实的 SSR / SEO / 公开门户需求；
3. 需要 TypeScript 强类型来防止线上事故（例如契约字段被误用已造成 ≥ 3 次故障）；
4. 需要复杂状态管理或大量第三方 UI 组件。

迁移成本预估：页面逻辑本身是标准 ESM，`core/` 与 `components/` 可直接复用，
主要工作量在把 `h()` 调用改为 JSX、把 `feature.json` 改为路由配置 —— 约 3–5 人日。
