## 一、任务契约（每个任务必须写全这 8 项）

之前那版任务书最大的问题是**任务与理由、记录、数字混在一段散文里**，读的人分不清
"这是要我做什么"还是"这是前人踩过的坑"。本版把任务压成一张固定结构的卡片：

| 字段 | 含义 | 不写会怎样 |
|---|---|---|
| **交付物** | 做完之后，什么东西从"没有"变成"有" | 任务变成一句口号，谁都不知道何时算完 |
| **现状证据** | `文件:行` + 一句实测 | 别人无法判断这个问题还存不存在 |
| **写入范围** | 这个任务**独占可写**的文件 | 两个人同时改一个文件 → 返工 |
| **禁止触碰** | 明确不能改的文件 | 顺手改了共享文件 → 打崩别人 |
| **接口冻结** | 本任务不能改的契约 | 各写各的字段 → 联调才发现对不上 |
| **验收** | **一条能跑的命令** + 期望输出 | "人工看一眼"等于没验收 |
| **依赖** | 必须先完成的任务 | 按不存在的接口写代码 |
| **规模** | 粗估（S ≤ 半天 / M ≤ 2 天 / L > 2 天） | 排期失真 |

**合并规则**：一个任务 = 一个 PR = 一个 squash 提交。分支 `feat/<任务ID>-<简述>`。
