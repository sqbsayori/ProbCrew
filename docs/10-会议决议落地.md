## 二、需修正（建议按这里的口径执行，理由附后）

### 修正 1 ·「课程视频冗余」不能顺手砍掉"读视频进度"能力

- 会议结论：视频不收集 ❌ 正确；但如果延伸成"助手不用管视频" ⚠️ **会砍掉产品核心能力**。
- 事实：助手要能回答"**我学到哪了**"，靠的就是读当前页面 `<video>` 的 `currentTime / duration`。
  这是**读当前页面**，不是**自建视频库** —— 两件事。
- 代码现状：`frontend/widget/extractor.js` 已实现该能力，`docs/09` 列为页面助手能力之一。
- **执行口径**：B6（课程视频素材）永久放弃；**视频进度读取保留**。

### 修正 2 ·「大家在研究开源数据集」的优先级需要重排

- 会议倾向：前期重点研究开源数据集（数学题库 / 嵌入+重排 / 教育作答）。
- 风险：这三件事**价值差一个数量级**，平铺会浪费最稀缺的资源（时间）。
- 按"是否卡住主线"重排：

| 项 | 作用 | 是否卡主线 | 建议 |
|---|---|---|---|
| **A3 嵌入 + A4 重排** | 语义检索。**每个 Agent 都要调检索，是所有能力的地基** | **卡**（不升级，M2 就一直是关键词匹配） | **最高优先级，本周就做** |
| **A1/A2 数学题库** | 量出"我们的解题准确率是多少" | 不卡，但没有它 M4 无法验收 | 次优先，与 C1 合并做 |
| **A6 教育作答数据** | 只验证知识追踪算法实现 | 不卡，且 **B 线已挂起** | **最低**，等主线告一段落 |

- **执行口径**：不是"三个人各研究一个数据集"，而是**先集中做 A3+A4**（一个人主攻足够），
  其余两项各出一份"可用性结论"即可，不必深入跑通。

### 修正 3 ·「历年考题暂时拿不到」→ 这直接决定了 M4 的验收方式

- 原计划 M4 是"用真实题目量准确率"。
- 现状：真题拿不到 → 必须**自制基准**（`docs/09` 的 C1：概率论题 + 标准答案 + 知识点标注，≥100 道）。
- **执行口径**：C1 **提前**，且**从教材习题整理**（不依赖老师给真题）。要求：逐题核对答案，
  **答案必须能用 SymPy 独立复算** —— 否则我们自己都不知道标准答案对不对。

### 修正 4 ·「默认分支换成精简骨架」有两种做法，效果差别很大

- 会议只说"换成精简后的可用框架"，没说**旧的完整演示去哪**。
- **执行口径（推荐）**：给当前完整演示打 **tag `v0.1.0-prototype`**，然后**直接精简默认分支**。
  - 好处：答辩/展示随时 `git checkout v0.1.0-prototype` 拿回完整演示；默认分支对新人**零干扰**。
  - 不推荐"新建一个分支当默认再慢慢删"——两套代码长期并存，合并会持续打架。
- 精简原则（重要）：**删页面，不删骨架**。
  - 保留：契约层、事件协议、自动发现（`app/agents` `app/tools` `app/api`）、
    一个最小闭环（`/api/chat/stream` → 一个 Agent → verifier → HITL → 前端最小壳）
  - 删除：纯展示型页面、与主线无关的演示内容、`docs/08`（B 线，已挂起）、过期的原型声明

### 修正 5 ·「老师审查 PR」在流程上是走不通的

- 现实：老师不会用 GitHub。分支保护**要求 PR**，但**审查人只能是团队成员**。
- 已有约束：GitHub 禁止自己批准自己的 PR，所以**负责人不能批准自己的 PR**。
- **执行口径**（任一）：
  - (a) **交叉审查**：A 的 PR 由 B 审并合并，B 的由 A 审 → 需要给 2 人以上仓库 write 权限；
  - (b) **负责人自合并**：保持现状（0 个必需批准），负责人自己按检查结果合并 → 最简单，但无 review。
  - 建议 (a)：既满足"经过审查"，又不需要老师参与。

## 五、需要同步给团队的三条工程约定

1. **分支**：`feature/xxx` → 合到 `dev` → 由负责人合到 `main`。
   - `feature → dev` 用 `--squash`；`dev → main` 用 `--merge`（**绝不 squash dev**，会分叉历史，我们踩过）。
2. **只增不改**：契约层（`contracts/`）只允许新增字段，改字段必须走 ADR。事件协议是前后端唯一约定。
3. **新人加一个功能只动自己的目录**：
   - 加 Agent → 放 `backend/app/agents/xxx.py`（写 `SPEC` + `run()`），自动被发现
   - 加工具 → 放 `backend/app/tools/xxx.py`（`@tool` 装饰器）
   - 加接口 → 放 `backend/app/api/xxx.py`（导出 `router`）
   - 加页面 → 放 `frontend/app/features/xxx/`（`feature.json` + `index.js`），跑一次生成脚本
   - **不需要改任何公共文件** —— 这是并行开发不打架的关键
